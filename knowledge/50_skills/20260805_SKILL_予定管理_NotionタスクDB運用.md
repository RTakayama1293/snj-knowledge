## 3. 検索キー方式（v2: 半日分割キー）

`notion-search`はセマンティック検索で1回最大10件、日付プロパティでのフィルタ不可。書き込み時にメモ末尾へ検索キーを埋め込み、取得時はキーで確実にヒットさせる。

```
@YYMMDDA — 午前（開始時刻が12:00より前）
@YYMMDDP — 午後（開始時刻が12:00以降）
@YYMMDDD — 終日（時刻なし）
```

- 例: 2026年2月25日 10:00開始 → `@260225A`／14:00開始 → `@260225P`／終日 → `@260225D`
- メモ末尾に改行して付与。メモが空ならキーのみ
- リスケ時は旧キーを新キーに置換（時間帯サフィックスも再判定）
- 複数日イベントは開始日のみ。旧形式`@YYMMDD`を見つけたら新形式に自動変換
- ステータス変更のみの場合はキー変更不要

## 4. 操作パターン

### 4.1 予定作成

最低限必要: 内容＋日時。推測で埋めてよいもの: 種別（MTG・訪問→打合せ、提出期限→締め切り、展示会・出張→イベント）、カテゴリ、ステータス（未来なら未着手）、所要時間（start/endから計算）、追加日（今日）、検索キー。

```
parent: { data_source_id: "9c3db177-51c3-4ddb-8858-b21029dfc9fe" }
properties:
  タスク名 / 種別 / カテゴリ / ステータス / 所要時間
  date:予定日時:start: "2026-02-25T13:00:00+09:00"
  date:予定日時:end: "2026-02-25T14:00:00+09:00"
  date:予定日時:is_datetime: 1（終日は 0・startは日付のみ）
  date:追加日:start: "2026-02-25"／date:追加日:is_datetime: 0
  メモ: "補足\n@260225P"
```

### 4.2 予定一覧取得（取得プロトコル）

1. **半日分割検索**: 対象期間の各日 × 3キー（A/P/D）で `notion-search`（data_source_url指定）
2. **オーバーフロー検出**: いずれかがちょうど10件なら、カテゴリ名を添えて追加検索（`@260225P 見込客` 等）。それでも10件ならユーザーに取りこぼし可能性を通知
3. **ステータス補完検索**: `未着手 進行中` で1回検索し、検索キーなし・旧形式キーの予定を拾う
4. **重複排除＋fetch検証**: ページIDで重複排除し、期間内か `notion-fetch` で確認（補完検索分は必ずfetch）
5. 表形式で出力（日付・時間・タスク名・種別・カテゴリ・ステータス）＋取得件数

### 4.3 予定更新・リスケ

- リスケ: 予定日時変更＋検索キー置換（既存メモをfetchしてキー部分のみ書き換え）
- ステータス変更・メモ追記: 検索キーは末尾に維持
- 曖昧な指定（「DENBAの件」等）は検索して複数ヒットなら確認、1件なら即操作

### 4.4 Excel出力・工数集計

- 出力列: 日付/曜日/開始/終了/タスク/種別/カテゴリ/所要時間/ステータス。ファイル名 `[YYYYMMDD]_DATA_タスクリスト.xlsx`
- カテゴリ=「定期」はデフォルト除外。完了は含めて灰色表示
- 工数集計は所要時間プロパティをカテゴリ別・期間別に合算
- ※業務タスク側の工数・マトリクス集計はGitHub Issue一覧から生成する（運用ルール §4）

## 5. 運用ルール

- **種別の判断**: タスク=一人作業の時間枠 / 打合せ=他者とのMTG・訪問 / 締め切り=提出・報告期限 / イベント=展示会・出張等の複数日もの
- **カテゴリの判断**: 見込客=営業活動 / ワークフロー=社内業務（月次・経費・稟議等） / EEZO=EC関連 / 調査=リサーチ / 定期=繰り返し定型 / その他
- **繰り返し予定**: カテゴリ=「定期」で1件だけ登録。月ごとに複製しない
- **完了予定は実績記録**: 完了のまま変更しない。未決事項が残る場合は「定期ウォッチ」を別途作成し、元エントリのメモに「→定期ウォッチへ移行」と記載
- 操作後は「完了/対象/次」の3行で結果報告
