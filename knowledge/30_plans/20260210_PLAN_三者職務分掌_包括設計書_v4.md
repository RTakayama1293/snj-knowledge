### 3-2. 飛石さん：詳細設計【v4更新】

**公式肩書**: 営業事務（内勤営業兼務）
**実態**: 管理部（スタートアップバックオフィス一人目）
**勤務形態**: 時短勤務 80-100h/月（9:30-15:30想定）

#### v4での根本方針変更：インサイドセールスではない

2/10蜂巣MTGにて確定：**飛石さんに売上コミットさせるイメージはない。** 稟議上の「内勤営業」は看板であり、実態は管理部。売上目標はチーム合算（C7）で吸収し、飛石個人のKPIは管理層としての業務品質で測定する。

これにより、v3の設計思想「営業が売る、仕入が買う、その間と周辺の全部」がそのまま公式方針として確認されたことになる。

#### JD提示：パターンA/B選択式【v4新規】

蜂巣さん方針：飛石さん本人にJDと時間配分を2パターン提示し、選んでもらう。

**パターンA：管理部フォーカス**

v3で設計した業務をそのまま実行。経理・総務・与信・管理会計のコア業務に集中する。

| 業務領域 | 月間工数 | 内容 |
|---------|---------|------|
| 受発注事務 | 20-23h | 受注→発注→請求→入金確認サイクル |
| ガリレオ運用 | 9-14h | 仕訳確認・入金消込・売掛残高・松田連携 |
| 与信管理 | 3-5h | 信用調査手配・評点記録・枠突合 |
| 総務庶務・証憑管理 | 15-20h | 備品・郵送・文書管理・電帳法対応 |
| 契約管理 | 2-3h | テンプレ管理・期限管理・締結前チェック |
| 月次管理会計 | 5-8h | Phase 2（7月）から段階的導入 |
| **合計** | **54-73h** | キャパ80-100hに対して余裕あり |

特徴：安定的。仕組み構築に集中でき、Phase移行が予測しやすい。「やるべきこと」が明確。

**パターンB：管理部＋リーガル経験の延長線上で拡張**

パターンAの管理部コア業務に加え、飛石さんの過去の法務・総務経験を起点に管理部の外へ染み出す提案型のJD。

| 業務領域 | 月間工数 | 内容 |
|---------|---------|------|
| パターンAの全業務 | 54-73h | 管理部コアは同じ |
| 取引条件の標準化 | +2-4h | 契約書審査から一歩進んで、取引条件テンプレートの整備、条件交渉の下準備 |
| コンプライアンス体制 | +1-2h | 輸出管理・食品表示・PL法対応の社内チェックリスト整備 |
| リスク管理 | +1-2h | 過去のトラブル事例の蓄積と再発防止策の仕組み化 |
| **合計** | **58-81h** | キャパ内だがパターンAより余裕は少ない |

特徴：飛石さんのキャリア形成としての広がりがある。「法務のわかるバックオフィス」という市場価値。ただし、キャパに余裕が少なく取引量増加時に圧迫されやすい。

**提示のポイント**

- 2パターンをそのまま見せ、本人に選んでもらう（蜂巣方針）
- どちらを選んでもPhase 1（4-6月）のやることは同じ（ガリレオ習得・契約書棚卸し・与信フォーマット整備）
- パターンBの拡張業務はPhase 2以降に順次追加
- 選ばなかった方の要素も、キャパに余裕があれば後から取り込み可能

#### キャパシティの再評価【v4新規】

2/10蜂巣MTGで、松本さんの作業量について以下の再評価が行われた。

**蜂巣さんの思考プロセス：**

1. 定常出荷1件あたり10h、その他新規調査に月40h → 月10件がMAX
2. 初見：「月10件が限界？少なすぎないか」
3. 再計算：年間100M ÷ 60件出荷 ≒ 1件あたり平均167万円
4. 月10件 × 12ヶ月 = 年120件 → **年間200M相当**の処理能力
5. 結論：現状の輸出売上目標（37-52M）に対しては十分すぎるキャパ

**意味するところ：**

- 松本さんのキャパが足りないのではなく、キャパを埋める案件が足りない
- 月10件の天井に達するのは年間200M規模。現実的に2-3年は到達しない
- 7月判定で出荷件数が少なかった場合、それは松本さんの能力ではなく営業側の型C流入の問題
- 月30万で年200M対応可能 → コスト対効果は非常に高い

**実稼働のヒアリング：**

蜂巣さん方針として、永井さんや松本さん本人に実際にかかる時間をヒアリングしてもいい（文脈は問わない）。ヒアリングの目的は7月判定の精度向上。v3の型A/B/C工数見積もりを実績で検証する機会になる。

#### 7月判定基準

v3から変更なし。月間出荷件数ベース（7回以上→維持 / 4-6回→縮小 / 3回以下→大幅縮小）。

#### 稟議に必要な4要件【v4新規】

蜂巣MTGにて、黒田さんの継続には以下4点の裏付けが必要とされた。

**要件1：自動化できないこと**

黒田さんに依頼するリストは、単純なDB検索では作れない。

| リストの種類 | なぜ自動化できないか |
|------------|-------------------|
| エゾシカ提供店リスト | 店舗HPのメニュー確認、食べログ等の口コミ精査が必要。「エゾシカ」でDB検索しても出ない |
| ホテル料理長の個人名付きリスト | 人事異動で頻繁に変わる。公開情報が限られ、個別確認が必要 |
| 百貨店催事担当の直通先リスト | 代表番号からの取次ぎでは到達できない。過去の催事実績から担当者を特定する作業 |
| 特定食材を使う飲食店リスト | メニュー内容の確認が必要。「北海道食材」で検索しても使用食材まではわからない |

Sansanに登録済みの名刺情報やJIRAのパイプラインデータでは、「まだ接点のない潜在顧客」のリストは作れない。リスト生産は営業サイクルの最上流であり、人手による情報収集が不可避。

**要件2：リスト生産効率**

| 指標 | 数値 |
|------|------|
| 初回実績 | 11件/h |
| 標準化後見込み | 20件/h |
| 月間生産量 | 264-480件/月 |
| 年間生産量 | 3,168-5,760件/年 |
| 1件あたりコスト | 11-25円（年60-80万 ÷ 年間生産量） |

**要件3：営業活動に対する必然性**

営業サイクルは「リスト → アプローチ → 商談 → 受注」の順序で進む。リストがなければサイクルが始まらない。

```
黒田のリスト生産
    ↓
杉田・田嶋のDM・手紙・電話
    ↓
アポ獲得・商談
    ↓
受注・出荷
```

#### 政治的文脈：黒田 vs 飛石のトレードオフ【v4新規】

1. 蜂巣さんの責任として、自分が入れた人を切るのは避けたい

**v4の設計方針：**

逆に3ヶ月で成果が出なければ、感情を排して切る判断をする。「数字で判断する」という原則はv2から一貫している。
