# ミナト内部参照：仮説構築・検証ガイドライン

## 基本原則
**仮説の価値 = 事実の強度 × 適用範囲の広さ × 検証可能性**

### 核心概念
- 「顧客が直接言ったこと」は最強の事実
- 事実の強度と適用範囲（類似プロファイル数）のバランスが重要
- セリングアイデア的発想：スケール可能性を常に考慮

## 事実強度評価システム（Lv.1-5）

### Lv.5: 最強事実（戦略直結可能）
**判定基準**: 顧客の具体的購買行動・明確な発言
**行動**: そのまま戦略化提案、類似先への横展開検討
**例**: 
- 加古川ヤマトヤシキの実際発注（50万円）
- 下関グランドホテル「カニと葉物仕入れたい」発言
- 宝塚阪急「定番ブランド脱却必要」発言

### Lv.4: 強い事実（検証で戦略化）
**判定基準**: 業界専門家・関係者の証言
**行動**: 優先的検証、複数ソースでの裏付け取得
**例**: 料理長の食材評価、漁協の輸出実績証言

### Lv.3: 中程度事実（補強必要）
**判定基準**: 統計データ・市場調査結果
**行動**: 複数ソースでの補強、現場での確認
**例**: 業界レポート、統計データからの推論

### Lv.2: 推測事実（仮説検証要）
**判定基準**: 間接的証拠からの推論
**行動**: 仮説として扱い、検証計画策定
**例**: 市場規模からの需要推定

### Lv.1: 弱い事実（参考程度）
**判定基準**: 一般論・業界常識
**行動**: 他の事実との組み合わせでのみ使用
**例**: 「北海道ブランド人気」等の一般論

## 適用範囲評価（類似度マトリックス）

### 評価要素と配点（各1-5点）
1. **業態一致度**: 同一業態(5) → 全く異なる(1)
2. **規模類似度**: 同一売上帯(5) → 桁違い(1)  
3. **立地類似度**: 同一商圏(5) → 全く異なる(1)
4. **決裁構造**: 同一パターン(5) → 全く異なる(1)
5. **顧客層重複**: 完全一致(5) → 全く異なる(1)

### 類似度判定
- **20-25点**: 高類似（横展開高確率）
- **15-19点**: 中類似（検証価値あり）
- **10-14点**: 低類似（慎重検討要）
- **5-9点**: 不適用（別戦略必要）

## 仮説生成・評価プロセス

### Step 1: 事実強度判定
```
思考フローチャート:
顧客の直接発言・行動あり？ → Lv.5
　↓No
専門家・関係者証言あり？ → Lv.4
　↓No
統計・調査データあり？ → Lv.3
　↓No
間接的証拠あり？ → Lv.2
　↓No
一般論・常識レベル → Lv.1
```

### Step 2: プロファイル抽象化
```
適切な抽象化レベル:
- 具体的すぎ：「宝塚阪急のハヤシさん」（n=1）
- 適切：「観光地立地の中小百貨店催事担当」（n=20-50）
- 抽象的すぎ：「百貨店の人」（n=1000+）

目標：類似プロファイル10-100社程度
```

### Step 3: 仮説文構築
```
フォーマット:
「（プロファイル）は、（条件）において、（行動）する可能性が高い」

必須要素:
- 具体的なプロファイル定義
- 明確な条件設定  
- 検証可能な行動予測
```

### Step 4: 優先順位スコア算出
```
仮説スコア = 事実強度(1-5) × 適用範囲(1-5) × 検証容易性(1-5) × 売上インパクト(1-5)

優先度分類:
- 80点以上: 即座に検証
- 60-79点: 戦略的検証
- 40-59点: 機会があれば検証
- 39点以下: 後回し・保留
```

## 議論時の思考パターン

### 受け取った情報の処理順序
1. **事実強度の即座判定**
   - 「これ、誰がいつ言った？」
   - 「実際の行動を伴ってる？」

2. **適用範囲の評価**
   - 「似たような会社、他にもある？」
   - 「どのレベルまで抽象化できる？」

3. **検証可能性の確認**
   - 「どうやって確かめる？」
   - 「いつまでに検証できる？」

4. **売上インパクトの試算**
   - 「正しかったら、いくら売れそう？」
   - 「投資対効果は？」

### 質問パターン集
**事実強度確認**:
- 「その情報の情報源は？」
- 「実際の行動を伴っていますか？」
- 「他にも似たような事例ありますか？」

**適用範囲評価**:
- 「似たような特徴の会社、何社くらいありますか？」
- 「どこまで抽象化しても成り立ちそうですか？」
- 「地域や業態の違いは影響しますか？」

**検証計画**:
- 「それ、どうやって確かめましょうか？」
- 「検証にどのくらい時間かかりそうですか？」
- 「失敗した時の判定基準は？」

**優先順位**:
- 「今すぐ調べるべき？後でもいい？」
- 「他の仮説と比べてどうですか？」
- 「リソース投入する価値ありますか？」

## 具体例テンプレート（宝塚阪急ケース）

### 情報整理例
```
【収集事実】
- Lv.5: ロイズ催事の年複数回実施（実績）
- Lv.4: 「マンネリ化打破必要」発言（担当者証言・推定）
- Lv.3: 観劇客40-50代女性メイン（統計的事実）

【プロファイル】
「観光地立地の中小百貨店催事担当者」
類似先: 15-20社（推定）

【仮説】
「観光地立地の中小百貨店催事担当は、定番ブランド脱却において、ストーリー性のある北海道食材企画（50万円規模）を年1-2回実施する需要がある」

【スコア算出】
- 事実強度: 5点（直接発言）
- 適用範囲: 4点（15-20社類似先）  
- 検証容易性: 5点（即座確認可能）
- 売上インパクト: 4点（1,000万円規模）
- 合計: 80点 → 最優先検証
```

## 品質チェックリスト

### 良い仮説の条件
- [ ] 具体的な事実に基づいている（Lv.3以上）
- [ ] プロファイルが適切に抽象化されている（10-100社レベル）
- [ ] 検証方法が明確
- [ ] 売上への影響が試算されている
- [ ] 実行可能な期限設定

### 避けるべきパターン  
- [ ] 「たぶん」「一般的に」が多用されている
- [ ] 検証方法が曖昧
- [ ] プロファイルが抽象的すぎる・具体的すぎる
- [ ] 売上インパクトが不明
- [ ] 実行期限が非現実的

## 継続改善メトリクス

### 月次評価項目
1. **検証完了率**: 期限内検証達成度
2. **的中率**: 仮説が正しかった割合  
3. **スケール実現率**: 予測適用範囲の実現度
4. **売上貢献度**: 仮説起源の実売上

### 仮説進化パターン
```
初期仮説 → 検証 → 精緻化 → 再検証 → 確定仮説 → セリングアイデア化 → 営業戦略実装
```

## 緊急度判定ルール

### 即座対応（当日-3日以内）
- 事実強度Lv.4以上 AND 明日訪問等の機会あり
- 既存案件に直結する情報
- 競合優位性に関わる情報

### 優先対応（1週間以内）  
- 優先スコア80点以上
- 売上インパクト大（1000万円以上）
- 検証容易性高

### 計画的対応（1ヶ月以内）
- 優先スコア60-79点
- 戦略的価値高いが検証に時間要
- 複数仮説の組み合わせ検証

### 機会対応（タイミング次第）
- 優先スコア40-59点  
- 限定的だが確実な需要
- 他業務と並行して検証可能

このガイドラインを参照して、仮説に関する議論や分析の際に一貫した品質と論理性を保つこと。
