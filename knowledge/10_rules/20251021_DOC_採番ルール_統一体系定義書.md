# 新日本海商事 商品採番ルール定義書

**統一採番体系 v1.0**  
作成日：2025-10-21

---

## 1. 採番ルール体系の概要

新日本海商事（SNJ）では、仕入から受発注・納請までのビジネスプロセス全体を通じて、**複数の独立した採番体系**を運用します。各採番体系は特定のエンティティを識別し、プロセス内での役割を一目で把握できるように設計されています。

### 3つの独立した採番層構造

| 層 | コード | 役割 | タイミング |
|---|------|------|----------|
| **仕入依頼層** | SUP | 顧客からの需要に基づく仕入探索 | 営業が依頼受け取り時 |
| **商品層** | PRD | 価格確定後の商品マスタ管理 | 仕入先から見積受領時 |
| **案件層** | QOT/PO/RCV/INV | 営業案件の見積から請求まで | 営業が見積発行時 |

### 🔴 重要：SUPとPRDの関係性

- **N:N関係**：複数のSUPから複数のPRDが生まれる可能性がある
- **マッピング不要**：参照リンクは存在しない（独立管理）
- **トリガーは価格確定**：仕入先から見積受領した時点でPRDを採番

## 2. 仕入依頼（SUP）採番ルール

顧客（内部）からの「こんな食材が欲しい」という依頼を記録するためのコードです。営業から仕入先へ見積依頼を出すまでのプロセスで使用されます。

### 採番フォーマット

```
SUP_[依頼者コード]_[連番]_[品目名]_[想定客名]
```

### フィールド仕様

| フィールド | 仕様 | 説明 | 例 |
|----------|------|------|-----|
| **SUP** | 固定プレフィックス | 仕入依頼コード識別子 | SUP |
| **依頼者コード** | 2文字、営業者ごと | 営業者の初期化等 | SU（蜂巣）、YS（野瀬）、SK（杉田） |
| **連番** | 4桁、依頼者別リセット | 依頼者ごとに0001から採番 | 0001, 0002, ..., 9999 |
| **品目名** | 日本語（商品の通称） | 何の商品を探しているか | ホタテ、ウニ、エゾシカ、ニンニク |
| **想定客名** | 営業が想定する顧客先 | ターゲット顧客 | オーセント、日航大阪、川西阪急 |

### 実装例

```
SUP_SU_0002_ホタテ_日航大阪
SUP_YS_0015_エゾシカミンチ_オーセント
SUP_SK_0001_ウニ_川西阪急
SUP_SU_0003_ニンニク_楽水山
```

### 依頼者コード一覧

- `SU` = 蜂巣さん（常務）
- `YS` = 野瀬さん（営業）
- `SK` = 杉田さん（営業）
- `（他）` = 今後追加される営業担当者

## 3. 商品マスタ（PRD）採番ルール

仕入先から見積を受領し、価格が確定した時点で、EEZOおよび法人営業の**統一商品マスタ**として登録されます。この番号は顧客向けにも表示される重要な識別子です。

### 採番フォーマット

```
PRD_[事業体]_[仕入先コード]_[仕入先別シリアル]_[バリエーション]
```

### フィールド仕様

| フィールド | 仕様 | 説明 | 例 |
|----------|------|------|-----|
| **PRD** | 固定プレフィックス | 商品コード識別子 | PRD |
| **事業体** | 2-4文字 | 管轄する事業体 | `SNJ`（新日本海商事）、`EEZO`（マーケットプレイス） |
| **仕入先コード** | 3文字（既存維持） | 既存の仕入先マスタコード | NKH、AUT、YSS、NNS、HNM等 |
| **仕入先別シリアル** | 4桁（仕入先ごとリセット） | 仕入先ごとに0001から採番 | 0001, 0002, ..., 9999 |
| **バリエーション** | 2桁 | サイズ/色/内容量等の区別 | 00（標準）、01（大容量）、02（色違い）等 |

### 実装例

```
PRD_SNJ_NKH_0052_00   ← オーセント向け焼き菓子（標準）
PRD_SNJ_NKH_0052_01   ← オーセント向け焼き菓子（大容量パック）
PRD_EEZO_AUT_0001_00  ← EEZO向け商品（基本形）
PRD_SNJ_YSS_0103_00   ← 山下水産の商品
PRD_EEZO_NKH_0005_01  ← EEZO向け商品（バリエーション）
```

## 4. 案件コード（見積/発注/納品/請求）採番ルール

営業が見積を発行する際に、同一の案件番号を付与します。その案件番号は、受注後も引き継がれ、発注～納品～請求まで統一されます。

### 採番フォーマット

```
[プレフィックス]_[事業体]_[仕入先コード]_[シリアル]_[案件番号]
```

### プレフィックス種別

| プレフィックス | 用途 | 発行者 | 例 |
|-------------|------|--------|-----|
| **QOT** | 見積書 | 営業 | QOT_SNJ_NKH_0052_001 |
| **PO** | 発注書 | 営業 | PO_SNJ_NKH_0052_001 |
| **RCV** | 納品確認 | 仕入/業務 | RCV_SNJ_NKH_0052_001 |
| **INV** | 請求書 | 経理 | INV_SNJ_NKH_0052_001 |

### フィールド仕様

| フィールド | 仕様 | 説明 | 例 |
|----------|------|------|-----|
| **プレフィックス** | QOT/PO/RCV/INV | ドキュメント種別 | QOT, PO, RCV, INV |
| **事業体** | 2-4文字 | 管轄事業体 | SNJ、EEZO |
| **仕入先コード** | 3文字 | 取引仕入先 | NKH、AUT、YSS等 |
| **シリアル** | 4桁 | 商品シリアル（PRDと同値） | PRDの値を参照 |
| **案件番号** | 3桁（営業別） | 同一営業による案件番号 | 001, 002, ..., 999 |

### 実装例：フロー

```
【案件001】
QOT_SNJ_NKH_0052_001  ← 見積発行時（営業が「001」と付与）
  ↓ （受注確認）
PO_SNJ_NKH_0052_001   ← 発注時（同一案件番号を引き継ぎ）
  ↓ （商品受領）
RCV_SNJ_NKH_0052_001  ← 納品確認時
  ↓ （請求来社）
INV_SNJ_NKH_0052_001  ← 請求時

【案件002】
QOT_SNJ_AUT_0001_002  ← 別案件（異なる仕入先、案件番号002）
PO_SNJ_AUT_0001_002
RCV_SNJ_AUT_0001_002
INV_SNJ_AUT_0001_002
```

## 5. ビジネスフロー及び採番タイミング

### Phase 1：仕入探索フェーズ

```
【顧客対応】
営業：「北海道ホタテってありませんか？」
     ↓ 依頼内容メモ
     SUP_SU_0002_ホタテ_日航大阪  ← 【採番】
```

- **役割**：「これから探す」という依頼の記録
- **管理**：スプレッドシート/JIRA等で依頼リスト管理
- **次ステップ**：仕入先に見積依頼メール送信

### Phase 2：価格確定フェーズ

```
【仕入先対応】
仕入先から見積受領
     ↓ 納入条件確定
     価格 ¥5,000/kg、ロット 10kg、リードタイム 3日
     ↓
PRD_SNJ_NKH_0052_00  ← 【採番】
（CS-Cart商品マスタに登録）

📌 SUPとPRDの紐づけは不要
   仕入先が複数の見積形態を提案した場合、複数のPRDが生まれることも
```

- **役割**：「実在する商品」として確定
- **管理**：CS-Cart商品マスタ、SENDO在庫管理
- **特徴**：同一仕入先内での連番採番、バリエーション対応

### Phase 3：受発注フェーズ

```
【顧客への提案】
営業：「こういう商品はいかがですか？」
顧客：「いいですね、見積をください」
     ↓
見積書発行 → QOT_SNJ_NKH_0052_001  ← 【採番】
            ※営業が案件番号「001」を付与

顧客：「じゃあください」
     ↓
発注書 → PO_SNJ_NKH_0052_001  ← 同一案件番号
     ↓
商品到着
     ↓
納品確認 → RCV_SNJ_NKH_0052_001  ← 同一案件番号
     ↓
請求来社
     ↓
請求書 → INV_SNJ_NKH_0052_001  ← 同一案件番号
```

- **役割**：営業案件の全ドキュメント統一管理
- **案件番号の付与者**：営業（見積発行時）
- **継承ルール**：受注後、PO/RCV/INVで同一案件番号を使用

## 6. 実装ガイドライン

### CS-Cartへの反映

商品詳細ページ表示：
```
商品コード：PRD_SNJ_NKH_0052_00
商品名：洋菓子セット（NIKI HILLS）
...
```

- **表示対象**：PRDコードのみ（SUP/案件コードは不表示）
- **検索対象**：PRDコードが検索可能

### SENDO / JIRA への反映

- **SENDO**：PRDコードで在庫管理、事業体・仕入先で絞り込み可能
- **JIRA**：案件コード（QOT/PO/RCV/INV）でチケット管理、タスク連動

### シリアル採番の運用

```
仕入先NKHの商品：
PRD_SNJ_NKH_0001_00
PRD_SNJ_NKH_0002_00
PRD_SNJ_NKH_0003_00
...
PRD_SNJ_NKH_9999_00

新しい仕入先ABFを追加した場合：
PRD_SNJ_ABF_0001_00  ← 0001から開始（リセット）
PRD_SNJ_ABF_0002_00
```

**運用ポイント**：
- 各仕入先ごとに独立した0001スタート
- スプレッドシート/Googleシートで採番管理
- 新規仕入先追加時も同ルールで適用

### バリエーション管理

同じ商品でも異なる規格・形状の場合：

```
PRD_SNJ_NKH_0052_00  ← 標準（内容量 500g）
PRD_SNJ_NKH_0052_01  ← 大容量（内容量 1kg）
PRD_SNJ_NKH_0052_02  ← 業務用（内容量 5kg）

PRD_EEZO_YSS_0010_00 ← 通常パッケージ
PRD_EEZO_YSS_0010_01 ← ギフトパッケージ
```

**運用ポイント**：
- バリエーション00 = 標準品（基本形）
- 01, 02...は同一シリアル内でのバリエーション
- CS-Cart等で「親商品-子商品」の関係を設定

## 7. 旧体系からの移行ガイド

### 旧コード構造（廃止）

```
旧：YG-AUT-0002-000
    ├─ YG（カテゴリコード）← 廃止（分類は属性で管理）
    ├─ AUT（ブランドコード）← PRDの「仕入先コード」に相当
    ├─ 0002（商品番号）← PRDの「シリアル」に相当
    └─ 000（バリエーション）← PRDの「バリエーション」に相当
```

### 新コード構造（採用）

```
新：PRD_SNJ_AUT_0002_00
    ├─ PRD（プレフィックス）← 新規追加（コード識別子）
    ├─ SNJ（事業体）← 新規追加（事業体識別）
    ├─ AUT（仕入先コード）← 旧AUTを継続
    ├─ 0002（シリアル）← 旧0002に相当
    └─ 00（バリエーション）← 旧000を2桁に変更
```

### 移行時の注意点

- **旧コード廃止**：CS-Cart内で「前回と全く異なる番号を使用する」仕様
- **カテゴリ分類**：CS-Cart属性（category, subcategory）で管理
- **バージョン管理**：旧コード↔新コードのマッピング表を保持（必要に応じて参照）

## 8. FAQ & トラブルシューティング

### Q1. 同じ仕入先コードで複数の商品がある場合、シリアルはどうなる？

**A.** 仕入先コード内で連番採番します。

```
仕入先NKHからの商品：
PRD_SNJ_NKH_0001_00（焼き菓子セットA）
PRD_SNJ_NKH_0002_00（焼き菓子セットB）
PRD_SNJ_NKH_0003_00（チョコレート菓子）
...
```

### Q2. SUPとPRDが1:1対応することもあるか？

**A.** あります。但し、マッピングは管理不要です。

```
例：SUP_SU_0002_ホタテ_日航大阪
    ↓ 見積来社
    ↓ 価格確定
    → PRD_SNJ_NKH_0052_00

この場合、SUP-PRD間に参照は不要。
SUPは「依頼」、PRDは「商品」として独立管理。
```

### Q3. 案件番号が999を超えたら？

**A.** 営業ごとに001からリセットしてください。

```
営業A：001～999
営業B：001～999  ← 営業ごとに独立

案件フロー：
QOT_SNJ_NKH_0052_001  ← 営業A の案件001
QOT_SNJ_AUT_0001_001  ← 営業B の案件001（別営業）
```

### Q4. バリエーション00～99を超えた場合？

**A.** 通常は超えません。バリエーションは2桁（00～99）で十分です。

```
PRD_SNJ_NKH_0052_00（標準）
PRD_SNJ_NKH_0052_01（大容量）
PRD_SNJ_NKH_0052_02（ギフトパック）
...
PRD_SNJ_NKH_0052_99（最大値）

99を超える場合は、別シリアルで新規採番を検討。
```
