# 参照03 ステージ定義と出力フォーマット v2（案件整理エージェント用）

※本ファイルは配布コピーです。正本は計数管理基盤_全体設計書（改訂中）にあります。

## 1. 入力の分類（最初に必ず判定する）

コンタクト情報1件ごとに、以下の4分類のどれに該当するか判定する。複数該当も可（その場合は行を分ける）。

| 分類 | 判定基準 | 出力先 |
|------|---------|--------|
| A. 販売見込客 | 当社が「売る」相手との接点。まだ具体的な商談条件に入っていない | 見込客台帳 |
| B. 販売案件 | 予算・条件の具体的な話が始まっている（確度A相当以上） | 案件台帳 |
| C. 仕入先・パートナー開拓 | 当社が「買う」「委託する」相手との接点（加工場・蔵元・フォワーダー・SNS支援等の提案受領を含む） | 仕入先開拓台帳 |
| D. サンプル | サンプル依頼・発送・フィードバックに関する内容 | サンプル台帳 |

## 2. 確度定義（見込客・仕入開拓 共通スケール）

### 販売見込客（A）
| 確度 | 定義 |
|------|------|
| F | ターゲット（名前・担当者不明） |
| E | 名刺あり |
| D | 部署一致（担当者の職務が商材に関連） |
| C | 興味あり（関心を表明） |
| B | 課題あり（具体的なニーズを認識） |
| A | 予算あり（購入意思確認）→ 案件台帳へ昇格 |

### 仕入先・パートナー開拓（C）
| 確度 | 定義 |
|------|------|
| F | 候補リストアップ |
| E | 接触済み |
| D | 商品・規格・サービス内容の情報入手 |
| C | サンプル・見積・提案の入手 |
| B | 条件交渉中 |
| A | 条件合意 → マスタへ昇格 |

## 3. 案件ステージ定義（B: 案件台帳用）

| 進捗% | ステージ | 判定基準 |
|-------|---------|---------|
| 25% | 初回商談済 | 予算ありの相手と条件の具体的な話をした |
| 50% | 見積提出済 | 正式な見積書を提出した |
| 75% | 条件合意 | 価格・数量・納期の主要条件に口頭合意 |
| 90% | 発注待ち | 合意済み。初回発注・契約の最終手続き待ち |
| 100% | 受注確定 | 発注書受領または入金確認 |

## 4. 出力フォーマット（タブ区切りで出力すること）

### 見込客台帳（A）
```
No	KW	社名	営業	確度	昇格	進捗メモ
```

### 案件台帳（B）
```
案件No	KW1	KW2	KW3	KW4	KW5	商品	営業	仕向地	社名	単価(千円)	進捗%	進捗	受注予定	納品予定	進捗メモ
```

### 仕入先開拓台帳（C）
```
No	KW	社名	担当	確度	昇格	進捗メモ
```

### サンプル台帳（D）※13列版
```
依頼日	エンドユーザー	営業	部位	仕入先	有償/無償	発送日	追跡No	着日	FB日	FB内容	本発注	案件No
```
- 追跡No・着日・FB日が原文にない場合は「不明」（Shopify下書き注文・リードタイム計測との紐づけに使うため列は省略しない）

### 共通ルール
- 案件No・Noは新規なら「新規」と記載（採番は人間が行う）
- 進捗メモ: 「MMDD 何があったか →何が変わったか」形式。複数イベントは / 区切り、左が新しい
- 不明な項目は「不明」。空欄・推測禁止
- 単価等の金額は千円単位。出典が原文にない金額は書かない

## 5. 追加セクション（該当時のみ出力）

### 【マスタ変更候補】
価格・提供条件・在庫状況・取引条件の変化が読み取れた場合に出力する。
```
社名 / 変更項目 / 旧値→新値（不明なら新値のみ） / 出典（日付・発言者） / ⚠要人間確認
```

### 【ルール変更候補】
業務ルール・お作法の新設や改訂が議論・決定された場合に出力する。
```
ルール内容 / 決定or議論中 / 出典（日付・発言者） / ⚠要人間確認
```

### 【新規KW候補】
KWタグ辞書にない重要な切り口が登場した場合に提案する。

### 【BUマッチング】
案件（B）の場合のみ、KW一致率（共通タグ数÷案件タグ数）を計算して出力する。
```
案件KW: [タグ列挙] → 最も近いBU: BU-xx（一致率 xx%） / 40%未満の場合「マッチなし（新規BU候補の種）」
```

### 【新規BU候補】
どのBUにも40%以上マッチしないKWパターンが確認された場合に出力する（同パターンの過去出現に気づいた場合はその旨を添える）。
```
KWパターン / 該当案件（社名） / 単価・頻度の手がかり（出典つき、なければ不明） / ⚠要人間確認
```

### 【BU改訂候補】
台帳の実績（受注・リピート）がBU一覧の単価・頻度の値と乖離している場合に出力する。
```
BU-ID / 項目（単価/頻度/担当等） / 一覧の値→実績の値 / 出典（日付・案件） / ⚠要人間確認
```
※BUの値に合わせて実績側を書き換えないこと（参照01 お作法7）
