# EEZO PDCA管理フォーマット v2

**作成日**: 2026-05-11
**精度ゾーン**: 70%（判断材料）
**前版からの変更**: 6軸の重複問題を解消。売上因数分解 + QCDの2系統に再編。粗利率・販促効率はQCDのC（コスト）に統合。

---

## 1. 全体構造

```
EEZO PDCA管理

├─ 売上系（トップラインを伸ばす）
│   ├─ 客数    ファネル各段の転換率
│   ├─ 客単価  1回あたりの購入額
│   └─ 頻度    年間の購入回数
│
└─ QCD系（ボトムラインを守る・効率を管理する）
    ├─ Q: Quality    商品品質・食品表示・法規・UX品質
    ├─ C: Cost       粗利率・販促効率・想定外コスト
    └─ D: Delivery   配送・温度管理・欠品・リードタイム
```

### 切り分けルール

- **売上系**: 「数字を上げにいく」意図の施策。計画的に仕掛けるもの
- **QCD系**: 「数字を守る・効率を上げる・事故を防ぐ」意図の施策
- **同一事象が両方にまたがる場合**: 主たる影響先にカードを置き、副影響先を記載する
  - 例: 配送遅延 → D（主）。キャンセル発生分は C に副影響。リピート毀損は売上系「頻度」に副影響

## 2. 売上系: 客数（ファネル詳細分類）

売上 = **客数** × 客単価 × 頻度

客数 = リーチ × CTR × スクロール率 × 詳細閲覧率 × カート率 × 購入完了率

### ファネル段階定義

| 段階 | 軸ID | 定義 | 主な計測ポイント | 施策カテゴリ例 |
|------|------|------|-----------------|---------------|
| リーチ | N-1 | EEZOの存在を知る | 広告インプレッション、SNSリーチ、メルマガ配信数 | Meta広告出稿、IF投稿、オーガニック投稿、O2O（フェリー船内）、メルマガ配信 |
| クリック | N-2 | サイトに来る | CTR、プロフ→サイト遷移率 | 広告クリエイティブ改善、SNSプロフィール最適化、CTA設計 |
| スクロール | N-3 | ページを見回す | スクロール率、トップ→一覧遷移率、直帰率 | ファーストビュー改善、カテゴリ導線設計、ナビゲーション |
| 詳細閲覧 | N-4 | 商品を見る | 一覧→詳細遷移率、詳細ページ滞在時間 | サムネイル画像、商品名、一覧レイアウト |
| カート投入 | N-5 | カートに入れる | カート率、ATC率 | 商品コピー、ストーリー、価格表示、レビュー/UGC表示、CTA文言 |
| 購入完了 | N-6 | 買う | 購入完了率、カート放棄率 | 決済手段、送料表示、カート離脱リカバリメール、ゲスト購入 |

### チャネル別の温度マッピング

3ライン設計(3/26)のCH別CVR仮説との接続。同じ「N-1 リーチ」でもチャネルによって後段の転換率が全く異なる。

| チャネル | 温度 | N-1→N-2 CTR | N-4→N-5 カート率 | N-5→N-6 購入率 |
|---------|------|-------------|-----------------|----------------|
| CH1 Meta広告 | コールド | 2.0% | 4% | 45% |
| CH2 Instagram | ウォーム | 4.0% | 8% | 55% |
| CH3 メルマガ | ホット | 4.0% | 10% | 65% |

→ 施策カードには**どのチャネルの・どの段階を改善するか**を明示する。

## 8. 施策カードのフォーマット（v2）

```
■ 施策ID: [軸ID]-[連番]  例: N-5-003、C-2-001
■ 施策名: （20字以内）
■ 系統: 売上系 / QCD系
■ 軸: N-1〜N-6 / P-1〜P-4 / F-1〜F-3 / Q-1〜Q-4 / C-1〜C-4 / D-1〜D-4
■ 副影響先: （他の軸への波及があれば記載）
■ チャネル: CH1 Meta / CH2 Instagram / CH3 メルマガ / 全体 / 該当なし
■ 起案日: YYYY-MM-DD
■ ステータス: Plan / Do / Check / Act / 完了 / 中止

【Plan】
- 目的: なぜやるのか（1文）
- 仮説: こうすれば → こうなるはず
- 成功指標: 数値（変化前 → 目標）
- 期限: いつまでに検証するか
- コスト: 金銭 / 工数（h）
- 担当: 誰がやるか

【Do】
- 実施内容:
- 実施期間: YYYY-MM-DD 〜 YYYY-MM-DD

【Check】
- 結果: 指標の実績値
- 仮説との差分: 達成 / 上振れ / 下振れ / 想定外
- 学び:（1〜3行）

【Act】
- 判断: 継続 / 改善再実施 / 中止 / 展開
- 派生施策:（あれば施策IDを記載）
```

## 9. 蜂巣さん報告との接続

月次3点発表のうちEEZO分は、売上系とQCD系からそれぞれハイライトを選ぶ。

```
【EEZO 5月】

[売上系]
客数 N-5（カート率）: 仮説 2%→4%  →  結果 3.2%
  施策: UGCをShopify商品ページに埋込
  学び: 調理写真UGCはカート率に効く。パッケージ写真は効かない

頻度 F-2（季節接触）: 母の日LP → 購入12件、うち新規8件
  学び: ギフト需要は「自分用」より購入ハードルが低い

[QCD系]
D-1（配送品質）: 母の日3件遅延 → 1件キャンセル（C-4に損失計上）
  原因: 出荷判定が発送日2日前で間に合わなかった
  対策: 判定を4日前に前倒し。父の日で検証する
```

## 11. 運用方針

### 管理ツール

Notion DBで施策カードを管理。月次でExcel販売管理システム VIEW_層にサマリ転記。

### 月次サイクル

```
月初 ─┬─ Check: GA4/Shopify/UTMデータ収集 → 前月施策の検証
      ├─ Act:   継続/改善/中止の判断
      ├─ Plan:  今月の新規施策カード起票
      └─ 報告:  蜂巣さん3点発表に売上系+QCD系のハイライトを選定

月中 ── Do: 施策実行

月末 ── Check準備: データ取得・集計
```

### 施策カードの起票基準

- **売上系**: 「どの変数を・どれくらい動かすか」が言語化できたら起票
- **QCD系**: インシデント発生時は即時起票。予防的施策は月初Planで起票
