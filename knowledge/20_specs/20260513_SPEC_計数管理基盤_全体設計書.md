## 1. 設計思想

### 1.1 基本原則

- **営業の入力負荷を最小化する**: 営業はSansanに1行書くだけ。Excelは開かない
- **構造化は高山が一元管理する**: Sansanコンタクトを週次で吸い出し、Excelに構造化転記
- **KWタグで案件とSIを接続する**: 案件もSIも複数KWタグの集合として定義し、タグ一致度でマッチング

### 1.2 4層データモデル

| 層 | 性質 | 説明 |
|---|------|------|
| マスタ | 定義・参照 | 何があるか |
| 計画 | 意図・目標 | どうしたいか |
| トランザクション | 事実・実績 | 何が起きたか |
| ビュー | 集計・突合 | 計画vs実績で今どうか |

計画はトランザクション（起きた事実）でもビュー（導出される集計）でもない。人間が意思を持って入力する目標値であり、独立した層として扱う。

## 2. ツール配置

### 2.1 各ツールの役割

| ツール | 役割 | 誰が使うか |
|--------|------|-----------|
| Sansan | 顧客マスタの本籍地 + 活動記録 + メルマガ配信 | 杉田・田嶋（入力）、高山（CSV吸い出し） |
| Excel（案件管理PT） | パイプライン管理 + SI管理 + ダッシュボード + 全社P/L | 高山（構造化・集計） |
| Excel（SENDO） | 受発注の実体。案件明細・経費・収支 | 営業（受発注入力）、高山（集計） |
| Excel（EEZO販管） | BtoC専用。カテゴリ別予実 | 高山 |
| Shopify | EEZO受注データの発生源。注文CSV | 自動 → Excel PQ取込 |
| JIRA | 複数人のタスクアサイン・期限管理 | 全員 |
| Notion | 高山個人のタスク・カレンダー | 高山 |

### 2.2 Sansanの位置づけ

Sansanの月額コストは「顧客データベースの自動メンテナンス費用」として正当化する。案件管理機能は使わない（機能性が低いため）。

Sansanが担うこと:
- 名刺取込・データ化（OCR＋人力校正）
- 人事異動の自動追跡
- 企業情報の自動付与（業種・従業員数・売上規模）
- メルマガ・DM配信
- コンタクト（活動記録）— 営業のスマホ入力の窓口
- KWタグによる見込客分類
- Excelへの顧客マスタCSVエクスポート（週次）

Sansanが担わないこと:
- 案件管理（Excelで行う）
- 構造化データ（単価・頻度・確度の管理はExcel）

### 2.3 JIRAの位置づけ

タスク管理専用。計数管理の19テーブルには含まれない別軸の機能。

- SI定例のアクションアイテム起票
- 複数人への担当アサイン・期限管理
- 案件番号（ANK-xxx）でExcel案件台帳と人間が紐づける（システム連携はしない）

Notion（高山個人タスク）との棲み分け: 自分だけ見ればいいもの→Notion、他人にアサインするもの→JIRA。

### 3.2 各テーブルのカラム定義

#### T5. SIマスタ

SIはKWタグの集合として定義する。案件台帳と同じKW列構造を持ち、タグ一致度でマッチングする。

| カラム | 型 | 説明 |
|--------|---|------|
| SI-ID | text | 採番。SI-01, SI-04, SI-04B, SI-10等 |
| KW1 | text | キーワードタグ1（例: 台湾, エゾシカ, 中堅国） |
| KW2 | text | キーワードタグ2（例: 独占権, 国内飲食） |
| KW3 | text | キーワードタグ3 |
| KW4 | text | キーワードタグ4 |
| KW5 | text | キーワードタグ5 |
| 商品 | text | 主力商品（日本酒, エゾシカ, DENBA等） |
| 担当 | text | 杉田 / 田嶋 |
| 想定単価 | int（千円） | 1回あたりの取引単価 |
| 頻度 | text | 月1回 / 月2回 / Q1回 |
| 目標社数 | int | このSIで狙う社数 |
| 年間金額 | int（千円） | 単価 × 頻度 × 社数 × 12 |
| Q1〜Q4 | int（千円） | 四半期配分 |
| 備考 | text | 自由記述 |

**起源の区分**: マニュアルSI（営業が定義）とクラスタSI（KW分析から提案）の2種類がある。クラスタSIは検証を経てマニュアルSIに昇格する。

#### T9. 見込客台帳

Sansanから週次CSV取込。確度A到達で案件台帳へ昇格。

| カラム | 型 | 説明 |
|--------|---|------|
| No | int | 連番 |
| KW | text | SansanのKWタグ（KW_エゾシカ等） |
| 社名 | text | 法人名 |
| 営業 | text | 杉田 / 田嶋 |
| 確度 | text | F / E / D / C / B / A |
| 昇格 | text | 空欄 or 「→案件」+案件No |
| 進捗メモ | text | Sansanコンタクトから転記。/区切り、左が新しい |

**確度定義（見込客フェーズ）**:

| 確度 | 定義 | 判定基準 |
|------|------|---------|
| F | ターゲット | 名前も担当者も不明。業態・地域でリストアップ |
| E | 名刺あり | 担当者の名刺を保有 |
| D | 部署一致 | 担当者の職務が商材に関連 |
| C | 興味あり | 商材への関心を表明 |
| B | 課題あり | 具体的な課題・ニーズを認識 |
| A | 予算あり | 予算規模・購入意思が確認できた |

A到達 → 案件台帳へ昇格。昇格済み行はグレーアウトして残す（転換率算出用）。

#### T10. 案件台帳

見込客台帳から昇格した案件。25%以降を管理。

| カラム | 型 | 説明 |
|--------|---|------|
| 案件No | text | 採番。ANK-001等 |
| KW1 | text | キーワードタグ1 |
| KW2 | text | キーワードタグ2 |
| KW3 | text | キーワードタグ3 |
| KW4 | text | キーワードタグ4 |
| KW5 | text | キーワードタグ5 |
| 商品 | text | 対象商品 |
| 営業 | text | 杉田 / 田嶋 |
| 仕向地 | text | 台湾 / アイルランド / 日本 等 |
| 社名 | text | 法人名 |
| 単価 | int（千円） | 1回あたりの取引単価 |
| 進捗% | text | 25% / 50% / 75% / 90% / 100% |
| 進捗 | text | ステージ名称（初回商談済 / 見積提出済 / 条件合意 / 発注待ち / 受注確定） |
| 受注予定 | date | YYYYMM |
| 納品予定 | date | YYYYMM |
| 進捗メモ | text | /区切り、改行なし、左が新しい |

**ステージ定義（案件フェーズ）** — 2026/5改訂版:

| 進捗% | 定義 | 判定基準 |
|--------|------|---------|
| 25% | 初回商談済 | 予算ありの相手と商談を実施。条件の具体的な話をした |
| 50% | 見積提出済 | 正式な見積書を提出した |
| 75% | 条件合意 | 価格・数量・納期の主要条件に口頭合意した |
| 90% | 発注待ち | 合意済み。初回発注 or 契約書の最終手続き待ち |
| 100% | 受注確定 | 発注書受領 or 入金確認。SENDOで受発注処理に移行 |

改訂理由: 旧75%「担当者OK、稟議中」/ 旧90%「稟議通過、ペーパーワーク待ち」は百貨店催事向けの定義。主要取引先（飲食店料理長・海外インポーター）に稟議プロセスが存在しないため、「条件合意」「発注待ち」に変更。稟議がある取引先の場合も包含する上位互換の定義。

**KW列の設計意図**: 案件のKWタグ群とSIのKWタグ群で同じ構造を持つ。タグ一致度（共通タグ数 / 案件タグ数）で案件→SIの自動マッチング候補を出せる。

---

### 3.3 SIの2類型

#### マニュアルSI（トップダウン）

営業がKWの組合せで「この型で売れる」と先に定義するもの。PFv5の16行がこれ。

- 起源: 営業の仮説・経験・蜂巣さんとの議論
- KW: 営業が意図的に設定
- 構造: KW群 + 単価 + 頻度 + 社数 + Q配分
- 更新: Q初め or SI追加時に高山+蜂巣で更新

#### クラスタSI（ボトムアップ）

案件台帳のKWタグ群から共起パターンを分析し、「こういう売り方の塊がある」と発見するもの。

- 起源: 案件KWの共起分析
- KW: 案件から抽出されたタグ群
- 構造: KW群 + 該当案件 + 件数 + 平均単価 + 仮説 + ステータス
- ライフサイクル: 仮説 → 検証中 → マニュアルSI昇格 or 棄却

#### マッチングロジック

```
一致率 = 共通タグ数（案件KW ∩ SI KW） / 案件タグ数

40%以上 → 自動紐づけ候補（濃緑）
1タグ以上一致 → 参考表示（薄緑）
0 → 紐づけなし
```

どのマニュアルSIにも40%以上マッチしない案件が蓄積した場合、そのKWパターンが新しいクラスタSIの種になる。

## 4. データフロー

### 4.1 入力フロー

```
【営業（杉田・田嶋）— Sansanのみ】
  名刺スキャン → KWタグ付け（KW_エゾシカ等）
  コンタクト入力（スマホ可）: MMDD + 何があったか + →何が変わったか

        ↓ CSV週次ダウンロード

【高山 — Excel構造化】
  コンタクトCSV → 差分確認 → 見込客台帳に反映
  確度A到達を判断 → 案件台帳に昇格（KW・単価・頻度を構造化）
  案件台帳の進捗メモにコンタクトから要約を/区切りで転記
```

### 4.2 集計フロー

```
【データソース】              【案件管理Excel】           【出力先】

Sansan 顧客CSV ──→ 見込客台帳
                    案件台帳 ──────→ ダッシュボード ──→ 蜂巣さん報告
                    SIマスタ ──────→                     定例MTG
                    マッチング表

SENDO 案件明細 ──→ 案件収支 ─────→ 月次予実 ─────→ 常務会資料
                                     全社P/L

Shopify CSV ────→ EEZO販管 ─────→ 全社P/L（EEZO分）
```

### 4.3 入力タイミング早見表

| いつ | 誰 | ツール | 何をする |
|-----|-----|--------|---------|
| 接触時 | 営業 | Sansan | コンタクト入力 + KWタグ付け |
| ステージ変化時 | 営業 | Sansan | コンタクトに「→見積提出」「→条件合意」等を明記 |
| 週次（月曜） | 高山 | Sansan → Excel | CSV吸い出し → 差分確認 → 案件台帳に構造化転記 |
| 週次（月曜） | 高山 | Excel | 見込客→案件の昇格判断 |
| Q初め | 高山+蜂巣 | Excel | SIマスタのQ配分更新 |
| 月次定例前 | 高山 | Excel | ダッシュボード更新 → 蜂巣さん報告用 |

### 4.4 コンタクト入力フォーマット

```
MMDD + 何があったか + →何が変わったか
```

例:
- `0512展示会名刺交換 エゾシカ精肉興味 →サンプル送付予定`
- `0522電話 7月100kg試し発注方向 →見積作成依頼`
- `0601受注確定 初回発注7月 →SENDO入力へ`

案件台帳の進捗メモ欄への転記形式:
```
0601受注確定 初回発注7月 →SENDO入力へ / 0522電話 7月100kg試し発注方向 →見積作成依頼 / 0512展示会名刺交換 エゾシカ精肉興味 →サンプル送付予定
```

/区切り、改行なし、左が新しい。
