## 改修の全体方針

### 設計原則
1. **案件番号は変えない** — 既存のVLOOKUP・証憑連携が全て案件番号依存。番号体系を崩すと全シート再設計になる
2. **バージョンは列追加で対応** — 案件番号の末尾にv2等を付けるのではなく、明細行にバージョン列を追加
3. **other行を廃止し、統一入力方式に移行** — M列（マニュアル列）を廃止し、全行が同じ列構造で入力できるようにする
4. **内税/外税は行単位で制御** — 仕入先マスタの税区分をデフォルト値として引き、行単位で上書き可能にする

### 改修の依存関係

```
[6. 統一入力方式] ←── 他の全改修の前提（列構造が変わるため最初にやる）
       │
       ├──→ [2. 内税外税] ←── 税区分列の追加は統一入力方式と同時に設計
       │
       ├──→ [1. バージョン管理] ←── バージョン列の追加も同時
       │           │
       │           └──→ [3. 案件収支] ←── バージョン別の収支計算が必要
       │
       ├──→ [4. 請求書とりまとめ] ←── 統一入力方式で税計算が正確になってから
       │
       └──→ [5. 要約/明細分離] ←── 行構造確定後に証憑テンプレートを改修
```

**着手順序: 6 → 2 → 1 → 3 → 4 → 5**

## 課題1: 同一案件のバージョン管理

### 発生シーン
- 見積提出後に数量変更 → 再見積
- 受注後に追加発注 → 明細追加
- 価格交渉で単価変更 → 明細修正

### 設計方針: 案件明細に「版」列を追加

#### 案件明細シートの変更

| 追加列 | 位置 | 内容 |
|--------|------|------|
| **版（Ver）** | No列の直後 | 1, 2, 3...（初版=1） |
| **版ステータス** | 版の直後 | 現行 / 旧版 |
| **変更理由** | 版ステータスの直後 | 数量変更 / 追加発注 / 価格改定 / etc |

#### 運用ルール
- 変更が発生したら、**変更対象行をコピーして新版行を追加**
- 旧行の版ステータスを「旧版」に変更
- 証憑テンプレートは**版ステータス=現行のみ参照**

#### 例: 2601-1001-S01 で数量変更が発生

| 案件番号 | No | 版 | 版ステータス | 商品名 | 数量 | 変更理由 |
|---------|----|----|------------|--------|------|---------|
| 2601-1001-S01 | 1 | 1 | 旧版 | 熊掌（後脚） | 4.781 | — |
| 2601-1001-S01 | 1 | 2 | **現行** | 熊掌（後脚） | 5.200 | 数量変更 |
| 2601-1001-S01 | 2 | 1 | 現行 | 送料 | 1 | — |

#### 証憑テンプレート側の変更
- VLOOKUP/INDEX-MATCH条件に「版ステータス=現行」を追加
- 見積書番号: EST-SNJ-2601-1001-S01 → EST-SNJ-2601-1001-S01**-R1**（Revision 1）
  - 初版はR無し、改訂時のみR1, R2...を付与

#### 案件追跡表への影響
- 追跡表は案件番号単位（1行）のため、バージョンの影響は限定的
- 「最新見積日」列を追加して版管理との連携を取る

### 想定リスク
- 旧版行が残ることで明細が肥大化する → フィルタで「現行のみ表示」をデフォルトにする
- 版コピーのオペミス → 版追加用マクロ（ボタン）を用意するかは運用負荷次第

## 課題2: 内税/外税対応

### 問題の構造
```
商品マスタ: 税抜価格で登録（外税前提）
    ↓ VLOOKUP
案件明細: 仕入価格列に税抜が入る
    ↓
発注書テンプレート: 税抜+消費税で出力
    ↓
仕入先からの請求: 内税（税込）で来る → 端数の齟齬が発生
```

### 設計方針: 行単位の税区分制御

#### 仕入先マスタへの追記
- 「仕入先見積税区分」列の未入力を全て埋める（外税 or 内税）
- 現状1社のみ → 全仕入先を棚卸し

#### 案件明細シートの変更

| 追加列 | 内容 | 初期値 |
|--------|------|--------|
| **仕入税区分** | 内税 / 外税 | 仕入先マスタからVLOOKUP |
| **仕入価格（税込）** | 内税時: 入力値そのまま / 外税時: 仕入価格×(1+税率) |
| **仕入価格（税抜）** | 内税時: 入力値÷(1+税率) / 外税時: 入力値そのまま |

#### 計算ロジック

```
IF 仕入税区分 = "内税":
    仕入価格（税抜） = 入力価格 ÷ (1 + 税率)
    仕入価格（税込） = 入力価格
ELSE:  （外税 = デフォルト）
    仕入価格（税抜） = 入力価格
    仕入価格（税込） = 入力価格 × (1 + 税率)
```

#### 証憑テンプレートへの影響
- **発注書**: 仕入先の税区分に合わせて出力形式を切替
  - 内税仕入先 → 税込価格で表示、「内税」表記
  - 外税仕入先 → 税抜+消費税の従来形式
- **見積書・請求書（販売側）**: 従来通り外税表示（自社の販売は外税統一）

#### 数量増加時の端数問題
- 内税の場合、税込単価×数量で計算し、端数は行合計で丸める（切捨て）
- 外税の場合は従来通り

### 想定リスク
- 同一案件内で内税行と外税行が混在する可能性 → 行単位制御なので対応可能
- 仕入先が見積もりごとに内税/外税を変える場合 → 行単位で上書き可能にしておく

## 課題3: 案件単位の収支計算シート

### 設計方針: 新シート「案件収支」を追加

#### 構造

```
案件収支シート
├── 入力: 案件番号（1つ入力すると全体が自動表示）
├── 売上セクション
│   ├── 商品売上（案件明細から集計、版ステータス=現行のみ）
│   ├── 送料売上
│   └── 売上合計（税抜）
├── 原価セクション
│   ├── 商品仕入（税抜ベースで集計）
│   ├── 送料原価
│   ├── その他原価（IM手数料等）
│   └── 原価合計
├── 粗利セクション
│   ├── 粗利額 = 売上合計 − 原価合計
│   ├── 粗利率 = 粗利額 ÷ 売上合計
│   └── 販管費按分（将来対応、現時点は空欄）
└── 版履歴セクション（過去版の収支サマリ表示）
```

#### 集計の仕組み
- SUMPRODUCT or SUMIFS で案件番号×版ステータス=現行をフィルタ
- 送料行の判定: 商品名に「送料」を含む or 商品カテゴリ列（後述）で判定

#### 案件明細への追加列

| 追加列 | 内容 |
|--------|------|
| **行種別** | 商品 / 送料 / 手数料 / その他 |

- 商品マスタからの自動入力行は「商品」
- other行は入力時に選択（デフォルト: 送料）

### バージョンとの連携
- 収支シートに「版」プルダウンを追加
- デフォルト: 現行版の収支を表示
- プルダウンで過去版を選択すると、その版時点の収支を表示
- → 「v1では粗利15%だったがv2で12%に下がった」が一目でわかる

## 課題4: 同一顧客別案件の請求書とりまとめ

### 発生シーン
- 同月内に同じ顧客（例: 日新堂）へ複数案件を納品
- 案件ごとに請求書を出すのではなく、月次でまとめて1枚にしたい

### 設計方針: 請求書テンプレートに「とりまとめモード」を追加

#### 新シート「請求とりまとめ」

| 列 | 内容 |
|----|------|
| 請求先顧客名 | プルダウン（案件追跡表の顧客名から重複除去） |
| 対象年月 | YYYY-MM |
| 対象案件一覧 | 自動表示（顧客名×対象年月×売上計上済みでフィルタ） |
| 除外フラグ | 個別に除外したい案件にチェック |

#### とりまとめ請求書テンプレート

```
請求書
├── ヘッダ: 顧客名、請求日、支払期限
├── 案件サマリ
│   ├── 案件番号1: 商材名 ¥xxx,xxx
│   ├── 案件番号2: 商材名 ¥xxx,xxx
│   └── ...
├── 小計（税率別）
│   ├── 8%対象: ¥xxx,xxx → 消費税 ¥xx,xxx
│   └── 10%対象: ¥xxx,xxx → 消費税 ¥xx,xxx
└── 合計: ¥xxx,xxx（税込）
```

#### 請求書番号の採番
- 通常請求: INV-SNJ-YYMM-1XXX-A01（案件紐づき）
- とりまとめ請求: **INV-SNJ-YYMM-C001-A01**（Cはconsolidated）
  - 月内連番で顧客ごとに1番号

## 課題5: 要約と明細の分離

### 発生条件
- 案件明細が一定行数（暫定: 10行以上）を超える場合

### 設計方針: 証憑テンプレートに要約/明細の2段構造

#### 見積書・請求書の出力モード

| モード | 条件 | 出力 |
|--------|------|------|
| 通常 | 10行未満 | 従来通り（1枚に全明細） |
| 分離 | 10行以上 | 要約ページ + 明細別紙 |

#### 要約ページの構成
```
【要約】
仕入先別サマリ:
  仕入先A: ¥xxx,xxx（12品目）
  仕入先B: ¥xxx,xxx（5品目）
送料: ¥xx,xxx
合計: ¥xxx,xxx（税込）

※明細は別紙をご参照ください
```

#### 実装方法
- 印刷範囲の動的制御（行数判定で切替）
- または要約専用シートを追加し、案件番号入力で自動集計

### 想定リスク
- 98行案件のような極端なケースでは別紙も複数ページになる → ページ区切り制御が必要
- Excel印刷の限界 → v1.0でPDF生成に移行する方が現実的かもしれない

## 課題6: 統一入力方式（M列廃止）

### 現状の問題
- 商品マスタにある商品 → 左側の列（col 4-13）に自動入力
- マスタにない商品（other） → 右側のM列（col 14-20）に手動入力
- **28%の行がother** → M列運用の負荷が大きい
- 2つの列を使い分ける認知負荷、入力漏れリスク

### 設計方針: 「入力ソース」列で制御し、全行が同じ列に入力

#### 新しい列構造

| 列 | 旧 | 新 |
|----|----|----|
| 商品ID | 維持 | 維持（空欄 or マスタID） |
| **入力ソース** | — | 新設: 自動 / 手動（商品IDの有無で自動判定） |
| 仕入先 | VLOOKUP | IF(入力ソース=自動, VLOOKUP, **直接入力**) |
| 商品名 | VLOOKUP | IF(入力ソース=自動, VLOOKUP, **直接入力**) |
| 仕入価格 | VLOOKUP | IF(入力ソース=自動, VLOOKUP, **直接入力**) |
| ... | ... | 同上 |

#### 実装: 数式の書き換え

現在（推定）:
```excel
= VLOOKUP($E3, 商品マスタ!$D:$Z, 列番号, FALSE)
```

新方式:
```excel
= IF($E3="", "", IF($E3="other", "", VLOOKUP($E3, 商品マスタ!$D:$Z, 列番号, FALSE)))
```

- 商品IDが空欄 or "other" → 数式は空文字を返す → **セルに直接上書き入力が可能**
- 商品IDがマスタIDの場合 → 従来通りVLOOKUPで自動入力

#### M列の扱い
- **M列（col 14-20）は削除**
- 既存other行のM列データを左側の列に移行（マイグレーション処理が必要）
- 集計数式（単価×数等）の参照先もM列参照ロジックを削除

#### マイグレーション手順
1. 現在のother行57行のM列データをバックアップ
2. 新方式の数式を全行に適用
3. other行の左側列にM列の値をペースト
4. M列を削除（非表示→確認期間後に完全削除）

### 想定リスク
- VLOOKUP数式が入ったセルに上書き入力すると数式が消える → **想定通りの挙動、問題なし**
- ただし一度手動に切り替えた後、商品IDを入力しても数式が戻らない → 入力ルール: 「マスタ商品に変更する場合は行を作り直す」
