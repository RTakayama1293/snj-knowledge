## 1. この会話で決まったこと

### 1.1 4層データモデル

| 層 | 性質 | テーブル数 |
|---|------|----------|
| マスタ（定義・参照） | 何があるか | 8 |
| 計画（意図・目標） | どうしたいか | 4 |
| トランザクション（事実・実績） | 何が起きたか | 7 |
| ビュー（集計・突合） | 計画vs実績で今どうか | 3 |

計画は独立した層。トランザクション（起きた事実）でもビュー（導出される集計）でもなく、人間が意思を持って入力する目標値。

### 1.2 ツール配置（確定）

| ツール | 役割 |
|--------|------|
| **Sansan** | 顧客マスタの本籍地 + 活動記録（コンタクト）+ メルマガ配信。案件管理機能は使わない |
| **Excel（SENDO）** | 受発注の実体 + **案件管理を統合する方針に変更**（後述） |
| **Excel（EEZO販管）** | BtoC専用。カテゴリ別予実 |
| **Shopify** | EEZO受注データ発生源。CSV→PQ取込 |
| **JIRA** | 複数人タスクアサイン・期限管理（計数管理の19テーブルとは別軸） |
| **Notion** | 高山個人タスク・カレンダー |

### 1.3 SENDO集約方針（会話終盤で決定）

当初は「案件管理PT（Excel）」「SENDO（Excel）」「EEZO販管（Excel）」の3冊体制だったが、**SENDOに案件管理を統合する方針に変更**。

理由:
- 案件管理PTとSENDOの二重管理（案件番号の対応関係が未決）が消える
- SENDOの案件番号採番のところに単価・金額・確度・進捗を入れれば1冊で完結
- Excel OnlineにアップすればA杉田・田嶋も閲覧可能

### 1.5 案件台帳の列構造（蜂巣さんと合意済み）

```
案件No | KW1 | KW2 | KW3 | KW4 | KW5 | 商品 | 営業 | 仕向地 | 社名 | 単価(千円) | 進捗% | 進捗 | 受注予定 | 納品予定 | 進捗メモ
```

- KWは複数列でタグ的に並ぶ
- 進捗メモは1セル、/区切り、改行なし、左が新しい
- セル結合は使わない

### 1.6 ステージ定義（2026/5改訂）

**見込客フェーズ（Sansan+Excel見込客台帳）**:
- F=ターゲット / E=名刺あり / D=部署一致 / C=興味あり / B=課題あり / A=予算あり
- A到達で案件台帳へ昇格

**案件フェーズ（SENDO案件台帳）**:
- 25%=初回商談済 / 50%=見積提出済 / **75%=条件合意** / **90%=発注待ち** / 100%=受注確定
- 旧75%「稟議中」→「条件合意」、旧90%「稟議通過」→「発注待ち」に改訂（飲食店・海外IMに稟議が不適合のため）

### 1.7 SIの2類型

| 類型 | 起源 | 説明 |
|------|------|------|
| マニュアルSI | トップダウン | 営業がKWの組合せで「この型で売れる」と定義。PFv5の16行 |
| クラスタSI | ボトムアップ | 案件KWタグの共起パターンから「こういう塊がある」と発見 |

- SIもKW複数列構造（案件台帳と同じ）
- タグ一致度（共通タグ数/案件タグ数）でマッチング。40%以上=自動紐づけ候補
- クラスタSIは仮説→検証→マニュアルSI昇格のライフサイクル
