# 20260630_SPEC_EEZO発送リスト自動化_v0.6

EEZO注文CSVを仕入先別の発送依頼書（Excel）へ自動変換する仕組みの最新仕様。
データ・コード・仕様を1枚に集約した参照用ドキュメント。

---

## 1. 概要

Shopify（eezo.club）の注文エクスポートCSVを入力し、各明細を**仕入先ごとに仕分け**して、仕入先に渡せる発送依頼書（Excel）を出力する。仕入先の判定はShopifyの商品メタフィールド `custom.supplier` を正とする。

```
orders_export.csv ──▶ eezo_order_split.py ──▶ 26-06-24_発送リスト_〇〇.xlsx（仕入先ごと）
                          ▲
                  supplier_map.json（仕入先マスタ）
```

---

## 2. ファイル構成

| ファイル | 役割 | 実行/参照 |
|---|---|---|
| **eezo_order_split.py** | 本体。仕分け・宛先補完・誤り検知・Excel出力 | `python eezo_order_split.py orders.csv` |
| **supplier_map.json** | 仕入先マスタ（商品名→仕入先・仕入先商品名） | 本体が同フォルダから読込 |
| **build_supplier_map.py** | マスタ全件リフレッシュ（Admin APIトークン使用） | ヘッドレス運用時のみ |
| 出力：`yy-mm-dd_発送リスト_〇〇.xlsx` | 仕入先別の発送依頼書 | 仕入先へ送付 |

---

## 3. データ仕様

### 3.1 判定の源泉（Shopify商品メタフィールド）

| メタフィールド | 表示名 | 用途 |
|---|---|---|
| `custom.supplier` | 仕入先 | **仕分けの判定キー**（例：オーセントホテル小樽、co-wild） |
| `custom.supplier_product_name` | 仕入先商品名 | 仕入先側の呼称。発送依頼書に併記し品の取り違えを防ぐ |

EEZOの表示名（顧客向け）は自由に変えてよい。仕分けは表示名ではなく `custom.supplier` で行うため崩れない。

### 3.2 supplier_map.json の構造

```json
{
  "小樽の2種テリーヌセット": {
    "supplier": "オーセントホテル小樽",
    "supplier_product_name": "ショコラテリーヌ＋ブルーチーズテリーヌセット"
  }
}
```

キー＝EEZO表示名（商品名）。照合時は空白（全角含む）を除去して突き合わせる。

## 4. コード仕様（処理フロー）

1. **CSV読込**：Shopify標準の注文エクスポート（UTF-8 BOM対応）。
2. **宛先の前方補完**：複数明細の注文は2行目以降の宛先が空欄になるShopify仕様に対応。注文番号（Name）単位で、宛先・依頼主・備考等の order-level 列を先頭行から補完する。
3. **仕入先判定**：各明細の商品名を `supplier_map.json` で照合。
   - 一致 → 仕入先＋仕入先商品名を採用（status: ok）
   - マスタに無い → 補助のキーワード一致を試行（status: fallback、信頼度低）
   - それでも不明／仮値／空 → **【要確認】グループへ隔離**（status: missing / placeholder）
4. **誤り検知**：仕入先名が仮値（「〜仕入先」「試験」「テスト」「サンプル」「コピー」「未定」「TBD」を含む）の場合は隔離。実行後に警告一覧を表示。
5. **Excel出力**：仕入先ごとに1ファイル。【要確認】は最後にまとめ、宛先空欄が残れば最終警告。

### 4.1 使い方（CLI）

```bash
python eezo_order_split.py orders_export.csv
python eezo_order_split.py orders_export.csv --map supplier_map.json --output-dir out
```

依存：`openpyxl`（`pip install openpyxl`）。

---

## 5. 出力仕様（発送依頼書 Excel）

- **ファイル名**：`yy-mm-dd_発送リスト_{仕入先名}.xlsx`（例：`26-06-24_発送リスト_オーセントホテル小樽.xlsx`）
- **シート構成**：タイトル行＋出力日/件数＋3グループ見出し（注文情報／依頼主（請求先）／送り先（送付先））＋ヘッダ＋明細
- **列**：注文番号／注文日／商品名(EEZO)／仕入先商品名／数量／依頼主一式／送り先一式／備考
- **体裁**：Meiryo UI、依頼主＝青系・送り先＝黄系の塗り分け、A4横・印刷フィット。電話番号は `0XX-XXXX-XXXX` に正規化。

## 6. 運用ルール

### 6.1 マスタ更新（2通り）

- **(a) チャット経由（推奨・トークン不要）**：「マスタ更新して」と依頼 → Shopifyコネクタで全商品の `custom.supplier` / `supplier_product_name` を吸い出し、新しい `supplier_map.json` を出力。
- **(b) ヘッドレス**：`build_supplier_map.py` を環境変数（`SHOPIFY_SHOP` / `SHOPIFY_TOKEN`、read_products権限）付きで実行。

### 6.2 新商品登録時のルール

`custom.supplier` を**必須入力**にする。未設定だと【要確認】に落ちる。仮の値（「〇〇仕入先」等）を入れない。

---

## 7. 既知の注意点

- **ファイル名衝突**：同一日に別バッチを出すと、同じ仕入先名のファイルが上書きされる。別バッチを併存させる場合は `--output-dir` を分けるか、ファイル名へ注文番号レンジ等を付す運用を検討。
- **表記ゆれ**：`custom.supplier` は完全一致で判定するため、「オーセントホテル」と「オーセントホテル小樽」は別グループになる。正式名称に統一すること（オーセントは「オーセントホテル小樽」が正）。
- **マスタの網羅性**：現行マスタは32商品の部分集合。未収録商品は【要確認】で拾えるが、運用前に全件リフレッシュしておくと安全。
