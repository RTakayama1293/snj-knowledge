## 1. 背景と経緯

### 3/24エディ定例での合意事項

- Shopifyフロント実装はほぼ完了。コレクション主導のページ生成が稼働し、コレクション単位で背景色・コピー・ストーリー・リンク先・商品フィルタを設定可能
- 社長FBの「会員登録でプロの世界に入る」コンセプトは合意済み
- B/C同居の実装・運用コストより、LP分離の方がむしろ軽いという仮説で合意
- サイトマップ/フローチャートを可視化し、社長含む関係者に提示して意思決定する方針

### 分離を推す根拠（エディ発言要旨）

1. **共通化の副作用**: 片方を変更すると他方にも影響が出る。にっちもさっちもいかなくなる
2. **ページ増≠運用コスト増**: コレクションを作ってページをアサインする仕組みができた時点で、ページが増えることの運用負荷は解消された
3. **公開制御の限界**: Shopifyはページを特定ユーザーのみに公開できない。CユーザーがB向けページに迷い込むリスクがある

## 2. 設計原則

### 2.1 分離の粒度

| レイヤー | 分離する | 共通化する |
|---------|---------|-----------|
| ドメイン | — | eezo.club 1つ |
| Shopifyストア | — | 1ストア |
| LP（コレクションページ） | B/Cで別ページ | — |
| 商品詳細（PDP） | B仕様/C仕様で各LP配下に配置 | 商品DB自体は共通 |
| レビュー/口コミ | — | 商品詳細ページ内の要素としてB/C共通参照 |
| カート/決済 | — | Shopify標準機能で共通 |
| 法定ページ/FAQ/会社概要 | — | 共通 |

ドメイン分離でもサブドメイン分離でもなく、同一Shopifyストア内でのコレクション分離。

### 2.2 ストーリーの共有と訴求の分岐

コア・ストーリー（産地・生産者・哲学・「一頭まるごと」文脈）はB/C共通。訴求の切り口だけが分岐する。

| 訴求軸 | BtoC | BtoB |
|--------|------|------|
| 主訴求 | 体験・ストーリー・レシピ | スペック・ISO・安定供給 |
| 価格表示 | 個人向け小分け単価 | MOQ・業務用ロット |
| CTA（未認証） | カートに入れる | 会員登録・認証依頼 |
| CTA（認証済） | カートに入れる | カートに入れる（B価格） |
| 信頼構築 | 口コミ・UGC・同梱カード | 認証・実績・取引先 |

B zoneは「問い合わせ誘導型」ではなく「認証ゲート型」。未ログインではCTAが会員登録・認証依頼、ログイン後はB価格でカート購入が可能。

例: ISO認証はプロには響くが一般消費者には業務っぽく映る（3/24高山所見）。

## 3. サイトマップ

### 3.1 全体構造

```
eezo.club（single Shopify store）
│
├── TOP page
│   ├── ヘッダーナビ: [エゾシカ] [ギフト] [法人の方] ...
│   └── ヒーロー → C向け訴求がデフォルト、Bはナビ経由
│
├── ── BtoC zone（購入誘導型）─────────────────────
│   │
│   ├── エゾシカC LP
│   │   ├── ストーリー（産地・猟師・一頭まるごと）
│   │   ├── C向け商品一覧（精肉カット/味付き加工品）
│   │   └── → 商品詳細(C仕様) → カート → 購入完了
│   │
│   ├── ギフトC LP
│   │   ├── 季節テーマ（母の日/父の日/お中元/お歳暮）
│   │   ├── 価格帯別セット（5K/10K/20K）
│   │   └── → 商品詳細(C仕様) → カート → 購入完了
│   │
│   └── フェリー乗客向けLP（O2O: 船内体験 → EC購入）
│       └── → 商品詳細(C仕様) → カート → 購入完了
│
├── ── BtoB zone（認証ゲート型）──────────────────
│   │
│   │   未ログイン → CTA: 会員登録・認証依頼
│   │   ログイン済 → CTA: カート購入（B価格）
│   │
│   ├── 法人認証 / 会員登録（「プロの世界に入る」入口）
│   │
│   ├── エゾシカB LP
│   │   ├── スペック・供給体制・認証
│   │   ├── B向け商品一覧（枝肉/業務用/半加工品）
│   │   └── → 商品詳細(B仕様) → カート(B価格) or 認証依頼
│   │
│   └── ギフトB LP
│       ├── 法人進物・株主優待・BtoE（福利厚生）
│       ├── 実績・対応可能ロット
│       └── → 商品詳細(B仕様) → カート(B価格) or 認証依頼
│
├── ── 共通ページ ─────────────────────────────
│   ├── カート / 決済（Shopify Payments / ギフト対応）
│   ├── マイページ / 注文履歴
│   ├── 問い合わせフォーム（toC/toB共用の一般問い合わせ）
│   ├── 会社概要
│   ├── FAQ
│   ├── 特定商取引法に基づく表記
│   └── プライバシーポリシー
│
└── ── 裏側（共通基盤）────────────────────────
    ├── 商品DB（B/C共通、SKUはB/Cで分離）
    ├── 配送設定（冷凍/冷蔵/常温）
    ├── メール通知（注文確認/発送通知）
    ├── 顧客セグメント（B/C/テスト群の管理）
    └── A/Bテスト基盤（Shopify顧客セグメント機能）
```

### 3.2 旧版からの変更点（3/30検討セッション）

| 変更箇所 | 旧 | 新 | 理由 |
|---------|-----|-----|------|
| B zone性質 | 問い合わせ誘導型 | 認証ゲート型 | 法人認証すればそのまま購入可能。問い合わせは不要 |
| B向けCTA | 問い合わせ・見積依頼 | 未認証→会員登録 / 認証済→カート購入 | 認証ゲートで購入完結型に |
| 海外向けLP | B zone内に配置 | 削除 | サイトマップからは除外 |
| フェリーLP | 「C寄り、将来拡張」 | O2O明記（船内体験→EC購入） | オフライン起点であることを明確化 |
| PDP配置 | 共通ページに1箇所 | 各LP配下にB仕様/C仕様で配置 | B/CでSKUが異なるため共通ページには置かない |
| レビュー/口コミ | 共通ページの独立項目 | 商品詳細ページ内の要素 | 商品に紐づく情報でありページ単位ではない |
| ギフトC LP子ページ | 季節テーマ別の子ページ | 商品詳細に直接遷移 | サイトマップとしては不要な粒度 |
| ギフトB LP | 商品詳細なし | 商品詳細（B仕様）追加 | B側にも商品詳細への導線が必要 |
| B向け問い合わせフォーム | B zone内に配置 | 削除 | 認証ゲート型では不要 |
| 問い合わせフォーム | 共通ページになし | 共通ページに追加 | toC/toB共用の一般問い合わせとして必要 |
| 法人認証/会員登録 | なし | B zone入口に追加 | 「プロの世界に入る」コンセプトの受け口 |
| 商品DB | 記載なし | 裏側（共通基盤）に追加 | B/C共通だがSKUは分離であることを明記 |

### 3.3 LP間の相互遷移

```
エゾシカC LP ←→ エゾシカB LP
  「法人・飲食店の方はこちら」/「個人のお客様はこちら」

ギフトC LP ←→ ギフトB LP
  「法人ギフト・大口のご相談はこちら」/「個人ギフトはこちら」

エゾシカC LP ←→ ギフトC LP
  「ギフトで贈る」/「自分用に選ぶ」

エゾシカB LP ←→ ギフトB LP
  「法人ギフト対応」/「食材仕入れ」
```

4つのLPは2軸（商品軸: エゾシカ/ギフト × 顧客軸: B/C）のマトリクスで相互リンク。

### 3.4 ユーザー導線フロー

**C向け（購入完了まで）**:
```
流入（Meta広告/Instagram/メルマガ/フェリーO2O）
  → エゾシカC LP or ギフトC LP or フェリーLP
    → 商品詳細（C仕様: ストーリー/体験/レシピ + レビュー）
      → カート（ギフトオプション: 熨斗/ラッピング/メッセージカード）
        → 購入完了 → メール通知 → 同梱カード体験
```

**B向け・未認証（認証完了まで）**:
```
流入（検索/紹介/展示会名刺/DM）
  → エゾシカB LP or ギフトB LP
    → 商品詳細（B仕様: スペック/規格/MOQ）
      → CTA「会員登録・認証依頼」
        → 法人認証フォーム → 審査 → 認証完了
```

**B向け・認証済（購入完了まで）**:
```
ログイン
  → エゾシカB LP or ギフトB LP
    → 商品詳細（B仕様: B価格表示/MOQ）
      → カート（B価格）
        → 購入完了 → メール通知
```

## 4. 商品カテゴリ別のB/C配置

全商品がきれいにB/Cに二分されない。カテゴリごとにグラデーションがある。

| カテゴリ | BtoB配置 | BtoC配置 | コレクション設計 |
|---------|---------|---------|---------------|
| エゾシカ精肉 | 飲食店卸（枝肉/ブロック） | 自家用（カット/ステーキ） | B/C各LPに別SKU |
| エゾシカ加工品 | BのクロスセルSKU | C主力（味付き焼肉等） | C向けLP主体 |
| ギフトセット | 法人進物/BtoE | 個人ギフト（季節LP） | C向け季節LP + B向けLP |
| 枝肉/原体 | B専用 | 非該当 | B向けLPのみ |
| ペットフード | OEM原料供給 | 犬飼い主向け完成品 | B向けLP + C向けLP |
| 菓子/常温加工品 | — | C向け（将来ギフトセット組込） | ギフトC LP内で展開 |

同一商品でもB/CでSKU・価格・訴求が異なるため、コレクション分離が合理的。

## 5. Shopify実装との対応

### エディ実装済みの機能との紐付け

| 実装済み機能 | サイトマップでの使い所 |
|------------|-------------------|
| コレクション主導のページ生成 | 4LP（エゾシカC/ギフトC/エゾシカB/ギフトB）+ フェリーLP |
| コレクション単位の背景色・コピー設定 | B/Cでトーンを変える（Cは温かみ、Bは信頼感） |
| コレクション複製→フィルタ差替 | 同一商品群からB/C別の商品リストを生成 |
| バッジ機能（全セクション対応） | SOLD OUT表示、NEW、B2B専用マーク等 |
| カスタムフィールド4種 | C仕様/B仕様の表示出し分け |
| ストーリーブロック（タイトル+本文+画像×複数） | 各LPのストーリーセクション |
| 顧客セグメント機能 | A/Bテスト、B/C顧客の分析 |

### 追加実装が必要な項目

| 項目 | 優先度 | 備考 |
|------|--------|------|
| TOPページのB/C分岐UI | 高 | ヘッダーナビ or ヒーロー下選択 |
| LP間相互リンクの配置 | 高 | 各LP内のヘッダー/フッター |
| 法人認証/会員登録フォーム | 高 | 「プロの世界に入る」入口。認証後にB価格購入を解放 |
| ログイン状態によるCTA切替 | 高 | 未認証→会員登録 / 認証済→カート購入（B価格） |
| ギフトオプション（熨斗/ラッピング） | 中 | C向け購入フローに必須 |
| 配送設定/メール通知 | 高 | 3/31着地の残タスク |
