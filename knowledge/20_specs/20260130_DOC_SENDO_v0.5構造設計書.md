# SENDO v0.5 構造設計書
## Excel + マニュアル運用版

**作成日**: 2026年1月30日  
**ステータス**: 運用開始  
**位置づけ**: SENDO統合営業DXプラットフォームのファースト版（MVP）

## 1. 概要

### 1.1 SENDOとは

**SENDO** = Strategic Execution Navigator for Data-driven Operation  
北前船の「船頭」をモチーフとした営業・受発注統合管理システム。

### 1.2 v0.5の位置づけ

| バージョン | 技術基盤 | 特徴 |
|-----------|---------|------|
| **v0.5（本版）** | Excel + 手動運用 | 運用ルール確立、証憑自動生成 |
| v1.0（計画） | DWH + 入力UI | Sansan連携、通知自動化 |
| v2.0（将来） | 完全自動化 | AI予測、EDI連携 |

**v0.5の設計思想**：  
システム化の前に「正しい業務フロー」を確立する。  
Excel関数による証憑自動生成で工数削減しつつ、運用ルールを固める。

## 2. システム構成

### 2.1 ファイル構成

```
受発注管理台帳.xlsx
├── マスタ系（参照用）
│   ├── 仕入先マスタ
│   ├── 商品マスタ
│   └── 顧客与信管理
├── トランザクション系（入力用）
│   ├── 案件明細 ←【主入力シート】
│   └── 案件追跡表 ←【進捗管理シート】
├── 証憑テンプレート系（出力用）
│   ├── 見積書
│   ├── 注文確認メール
│   ├── 発注書
│   ├── 納品書
│   ├── 請求書
│   └── 請求書（前払）
└── 補助系
    └── 入力ルール用シート
```

### 2.2 データフロー

```
【入力】                    【参照】                    【出力】
                              ↓
案件明細シート ──────→ 商品マスタ ──────→ 見積書
    │                  仕入先マスタ           発注書
    │                       ↓                請求書
    └──────────────→ 案件追跡表 ──────→ 注文確認メール
                            │
                            ↓
                      【進捗管理】
                      日付を埋めていく
```

### 2.3 シート間連携

| シート | 役割 | 入力/参照 | キー項目 |
|--------|------|----------|---------|
| 仕入先マスタ | 仕入先基本情報 | 参照 | 仕入先コード |
| 商品マスタ | 商品・価格情報 | 参照 | 商品ID |
| 顧客与信管理 | 与信限度・残高 | 参照 | 顧客名 |
| 案件明細 | 案件ごとの商品明細 | **入力** | 案件番号 |
| 案件追跡表 | 進捗ステータス管理 | **入力** | 案件番号 |
| 証憑テンプレート | 書類自動生成 | 参照（案件番号のみ入力） | 案件番号 |

## 3. 採番ルール

### 3.1 案件番号体系

```
YYMM-1XXX-A01
 │     │   │
 │     │   └── 担当者コード + 支店コード
 │     └────── 月内連番（1001から開始）
 └──────────── 年月（2601 = 2026年1月）
```

**担当者コード**：
| コード | 担当者 |
|--------|--------|
| S | 杉田 |
| T | 田嶋 |
| H | 蜂巣 |
| A | 永井 |
| K | 門永 |
| R | 高山 |

**支店コード**：
| コード | 支店 |
|--------|------|
| 01 | 大阪 |
| 02 | 小樽 |

### 3.2 証憑番号体系

| 証憑 | 形式 | 例 |
|------|------|-----|
| 見積書 | EST-SNJ-YYMM-1XXX-A01 | EST-SNJ-2601-1001-S01 |
| 発注書 | POC-SNJ-YYMM-1XXX-A01-ZZZ | POC-SNJ-2601-1001-S01-APK |
| 納品書 | DEL-SNJ-YYMM-1XXX-A01 | DEL-SNJ-2601-1001-S01 |
| 請求書 | INV-SNJ-YYMM-1XXX-A01 | INV-SNJ-2601-1001-S01 |
| 輸出書類 | EXX-A-YYMM-01 | EHK-A-2601-01（香港向け） |

**ZZZ = 仕入先コード**（アルファベット3文字）

## 4. 運用フロー

### 4.1 基本フロー（後払い）

```
1. 概算見積 ─→ 2. 与信確認 ─→ 3. 正式見積 ─→ 4. 受注
                                    │
                                    ↓
                               [見積書発行]
                                    │
                                    ↓
    ┌─────────────────────────────────┘
    ↓
5. 仕入発注 ─→ 6. 出荷予定 ─→ 7. 出荷 ─→ 8. 着荷
    │
    ↓
[発注書発行]
    │
    ↓
9. 仕入計上 ─→ 10. 仕入支払 ─→ 11. 売上請求 ─→ 12. 売上入金
                                    │               │
                                    ↓               ↓
                               [請求書発行]     [案件クローズ]
```

### 4.2 前払いフロー（分岐）

```
1. 概算見積 ─→ 2. 与信確認 ─→ 3. 正式見積 ─→ 4. 受注
                                                   │
                                                   ↓
                                          5. 売上請求【前払】
                                                   │
                                                   ↓
                                          [請求書（前払）発行]
                                                   │
                                                   ↓
                                          6. 入金確認
                                                   │
                                    ┌──────────────┘
                                    ↓
                          7. 仕入発注 → 以降は通常フロー
```

### 4.3 責任分担

| 役割 | 作業範囲 | 責任 |
|------|---------|------|
| 営業 | 概算見積～受注、進捗確認・催促 | **全ステップの責任** |
| 受発注 | 発注書作成、請求書発行、入金確認 | 作業担当（責任は営業） |
| 経理 | 支払処理、入金消込 | 経理処理 |

## 5. 証憑テンプレート仕様

### 5.1 自動生成の仕組み

```
案件番号を入力
    ↓
VLOOKUP/INDEX-MATCHで案件明細から取得
    ↓
・顧客名
・商品名・数量・単価
・合計金額（税込）
・納品先情報
・支払条件
    ↓
テンプレートに自動反映
    ↓
PDF出力 or 印刷
```

### 5.2 ヘッダー識別（モノクロ対応）

| 証憑 | ヘッダー | 識別ロジック |
|------|---------|-------------|
| 見積書 | 白背景＋黒文字 | 何もない＝見積 |
| 発注書 | 薄グレー背景＋黒文字 | 薄い背景＋黒文字 |
| 納品書 | 濃グレー背景＋白文字 | 濃い背景＋白文字 |
| 請求書 | 黒背景＋白文字 | 反転＝請求 |

**設計意図**：フロー順に濃くなる＝直感的に覚えやすい

### 5.3 注文確認メールの法的位置づけ

```
正式見積発行
    ↓
顧客が発注意思を表示（電話/メール）
    ↓
注文確認メール送信（見積書番号を明記）
    ↓
「翌営業日正午までにご連絡なき場合、確定」
    ↓
黙示の承諾 → 契約成立
```

## 6. 特殊ケース対応

### 6.1 不定貫商品（熊掌・エゾシカ等）

```
概算見積（推定重量）
    ↓
顧客と価格感を握る
    ↓
仕入先に実重量確認
    ↓
正式見積（実重量で発行）
    ↓
受注
```

### 6.2 リピート注文

```
毎回新規案件番号を付与
    ↓
見積書を再発行
    ↓
顧客から「この見積で発注します」の返信
    ↓
受注確定
```

**理由**：案件番号＝見積書番号の起点で統一し、追跡性を確保

### 6.3 急ぎ案件

```
正式見積＋注文確認メールを同時送付
    ↓
「お急ぎのため、見積書と同時にお送りします」を明記
```

**前提**：北海道→本州で3〜4日かかるため、真の緊急は稀
