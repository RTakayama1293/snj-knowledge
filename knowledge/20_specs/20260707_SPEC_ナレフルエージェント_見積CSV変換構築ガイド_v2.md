# ナレフルチャット エージェント構築ガイド v2 — 見積→商品マスタ変換（新SENDOモック）

**作成日**: 2026-07-07（v1: 同日）
**精度**: 70%（モック構築用たたき台。実機で回して調整する前提）
**元スキル**: Claude用スキル `quote-to-csv`（見積情報→商品マスタCSV変換）の委譲版
**v1からの変更**:
①送料計算の廃止 — 送料関連5列（標準国内送料率・標準国内送料・実績国内送料・国内送料・仕入単価+国内送料）を列ごと削除し、**33列→28列**に簡素化。送料条件は申し送り事項にテキスト記録
②位置づけの変更 — 現行SENDO0.5への取り込み補助ではなく、**新SENDO商品マスタ（v0.6検討）のモック**。本エージェントの28列出力＝新マスタ構造のたたき台であり、実運用で回して列構成の妥当性を検証する
③参照Aをv2（28列版）に差し替え
**目的**: 仕入先からの見積情報（PDF・Excel・メール本文の貼り付け）を渡すと、新SENDO商品マスタ（28列）形式のデータが返るエージェントを、この文書だけを見て組めること

**現行SENDO0.5との互換性（重要）**:
- 本エージェントの出力は**現行33列マスタには直接貼れない**（列数・順序が異なる）
- 移行期間中、現行マスタへの登録が必要な場合は従来どおりClaude（quote-to-csvスキル）で33列変換する
- 新SENDO商品マスタが28列で確定・稼働したら、Claudeスキル正本も28列版に更新する（Notionタスク起票）

**アップロードする参照ファイル（3本）**:
1. 参照A_列定義仕様_28列_v2.md
2. 参照B_大分類小分類マスタ.md
3. 参照C_正規化ルール.md

**エージェント紹介文**（コピペ用）:

```
仕入先からの見積情報（PDF添付・メール本文の貼り付け・価格表）を渡すと、新SENDO商品マスタ（28列）形式に変換します。
できること:
①見積から商品データを抽出し、大分類・小分類を自動判定
②税込価格の税抜変換（小数点保持）、単位・温度帯の正規化
③タブ区切りで出力（Excelにそのまま貼り付け可能）
④送料条件・支払条件等は申し送り事項に記録。不明・推定項目は「要確認事項」として最後にまとめて報告
使い方: 見積PDFを添付するか、見積メール本文を貼り付けて「変換して」と送信してください。
※出力は新マスタ（28列）形式です。現行SENDO0.5（33列）には直接貼れません。
```

## 画面2: 参照ファイル設定・応答設定

| 項目 | 設定値 | 理由 |
|------|--------|------|
| ファイル参照 | 参照A（v2・28列）〜Cの3本をアップロード | 参照Aは新マスタ構造の一次定義。エージェント側が当面の正本 |
| 参照ソースの詳細 | **表示する** | 分類判定・正規化の根拠を検証するため（モック段階では必須） |
| モデル | Sonnet 5・**拡張思考OFF** | 規律型の構造化抽出。拡張思考は税抜変換等の数値ミスが出た場合のみONに上げる（クレジット節約。頻繁に回す定型処理のため1回あたり消費を軽く保つ） |
| WEB検索 | **利用しない** | 見積に書かれた情報のみで変換させ、外部情報による創作を防ぐ |

**運用メモ**:
- 見積情報は参照ファイルに登録せず、**チャットに都度添付（または本文貼り付け）**する。参照ファイル＝変わらないルール、チャット入力＝案件ごとに変わるデータ、という役割分担は案件整理モックと同じ
- **参照Aの正本管理はv1と逆転している点に注意**: 28列構造は新設計のため、当面は本エージェントの参照A_v2が一次定義。実運用で列の過不足が見えたら参照Aを改訂し、構造が固まった時点で新SENDO（Excel）とClaudeスキル正本に反映する。この順番（モックで検証→Excel実装）がこのエージェントの存在意義
- 参照B・Cは従来どおりClaudeスキル `quote-to-csv/references/` が正本。正本更新時はエージェント側差し替えをNotionタスクに起票

## 画面2続き: ベースプロンプト（コピペ用・v2）

```
あなたは新日本海商事の商品マスタ登録アシスタントです。仕入先からの見積情報（PDF・貼り付けテキスト・価格表）を、新SENDO商品マスタ（28列）形式のデータに変換します。

# 動作モード（入力で自動判定）
【変換モード】見積情報が渡された場合:
1. 見積から商品ごとに、仕入先・商品名・単位・容量・仕入単価等を抽出する
2. 参照ファイル「大分類小分類マスタ」の選択肢から大分類・小分類を判定する。マスタにない分類を創作しない
3. 参照ファイル「正規化ルール」に従い、価格（税抜変換・小数点保持）・単位・温度帯・賞味期限を正規化する
4. 参照ファイル「列定義仕様」の28列を順序どおりに、1商品1行のタブ区切りで出力する
5. 以下の列は必ず空欄にする（Excel/新SENDO側で自動処理されるため）:
   商品連番・初出フラグ・シリアル・販売先利益率（上代加味）・海外定価（20％）・海外定価粗利・国内定価（15％）・国内定価粗利・画像名・EEZO掲載可否
6. 仕入価格更新日は本日の日付（YYYY-MM-DD）を入れる
7. 送料は計算しない。送料条件（送料別途・送料込み・○円以上無料・地域別運賃等）は見積の記載のまま「申し送り事項」列に入れる
8. 税率は食品・飲料0.08、酒類・非食品0.10で判定する
9. 出力の最後に【要確認事項】セクションを必ず見出し付きで出力する。内容: 推定した分類・温度帯、税込/税抜が不明で推定した価格、オープン価格・時価等の空欄項目、その他判断に迷った点。確認事項がなければ「なし」と書く
10. 最後に処理件数(何商品を変換したか)を1行で添える

【照会モード】列の定義・分類の判定基準・正規化ルールについての質問の場合:
参照ファイルの範囲で答える。参照ファイルにない情報は「定義にありません」と答える。

# 厳守事項
- 推測で埋めない。見積に書かれていない項目は空欄にする（必須列で不明な場合は「不明」と書き【要確認事項】に挙げる）
- 原文にない価格・数量・条件を創作しない
- 税抜変換時は小数点以下を保持する（丸めない。割り切れる場合のみ整数）
- 「○○円〜」「オープン価格」「時価」「要相談」は正規化ルールの特殊ケース処理に従い、価格を勝手に決めない
- 大分類・小分類は参照ファイルの選択肢からのみ選ぶ
- 28列の順序を変えない。列の追加・省略をしない。送料関連の列（送料率・国内送料等）は存在しないので出力しない
- 商品名・仕入先名は見積の表記のまま使う（勝手に略さない・正式化しない）
- 出力のデータ部分は必ずタブ区切り（Excelに直接貼れる形）にする。1行目にヘッダ（28列名）を付ける
- 支払条件・送料条件・在庫状況等の取引条件は「申し送り事項」列に入れる
```

**分岐判定の基本条件**（コピペ用）:


## 画面5: ワークフロー（実行後の条件分岐）

実行後（終了）をON。

| 優先度 | 判定条件（コピペ用） | アクション |
|--------|--------------------|-----------|
| 1 | 応答の【要確認事項】に、価格の推定・空欄（オープン価格・時価等）または分類の判定不能が含まれる場合 | **メールを送信する（送信先: オーナー）** |

**設計意図**:
- メール通知は**カネに関わる不確実性**（価格が確定できなかった・推定した）に限定する。温度帯や賞味期限の推定は貼り付け時の目視確認で拾えば足りるため、メール対象に含めない——精度配分ルールでいえば、仕入単価は100%ゾーン（取り込み後に発注・請求へ波及する）、それ以外の推定は70%ゾーン
- ベースプロンプトで【要確認事項】を必ず出力させている（なしの場合も「なし」と書かせる）のは、この判定を安定させるため

**将来拡張（モックでは未設定）**:
- 「次エージェントを指定して自動的に連続実行」で、①見積変換→②案件整理アシスタント（仕入先開拓のC分類コンタクトとして台帳行も生成）の2段パイプラインが組める。仕入先からの見積受領は多くの場合Sansanコンタクトとしても記録すべきイベントなので、この連結は相性がよい
- Webhook→Slackで、変換結果を仕入管理チャンネルへ直接流す

## テスト手順（5本）

### テスト1: 変換モード（正常系・テキスト貼り付け）
過去の実見積メール（例: 青果系の「アスパラGR・L（1束＝150g）」等、単位と容量が分離するもの）を本文貼り付けし、「変換して」と送信。

**期待される出力の骨子**:
- ヘッダ付き**28列**のタブ区切りで、Excelに崩れず貼れること
- **送料関連の列（送料率・標準送料等）が出力に存在しないこと**（旧33列構造を学習知識から混ぜてきたらNG。厳守事項の該当行を強調）
- 単位=束、容量=150g のように取引単位と内容量が正しく分離されていること
- 空欄指定列（商品連番・計算列群・画像名・EEZO掲載可否）が本当に空欄であること（0や「-」で埋まっていたらNG）
- 仕入価格更新日=当日、税率=0.08 が入っていること
- 見積に送料条件の記載があれば、計算されずに申し送り事項へテキストで入っていること
- 【要確認事項】と処理件数が末尾に付いていること

### テスト2: 税抜変換の精度
税込表記の見積（例: 税込715円・8%）を貼り付けて「変換して」と送信。→ 仕入単価が 662.037037 のように**小数点保持**で出ること。四捨五入して 662 になっていたらベースプロンプトの「丸めない」を強調する。数値ミスが直らない場合のみ拡張思考ONを検討。

### テスト3: PDF添付
実際の見積PDFを添付して「変換して」と送信。→ テキスト貼り付けと同水準で抽出できるか確認。**PDFの表組みが読めない場合はここで判明する**（読めなければ「PDFはテキスト貼り付けに変換してから渡す」運用に切り替え、紹介文を修正）。

### テスト4: 特殊ケース＋メール送信の確認
「オープン価格」「○○円〜」を含む見積を貼り付けて「変換して」と送信。→ 価格欄が空欄（〜は最低価格採用）＋【要確認事項】に列挙され、**オーナー宛メールが届くこと**。価格が創作されていたら厳守事項の該当行を強調する。

### テスト5: 照会モードと対象外
- 5a: 「メロンの小分類は？」と送信。→ 「野菜（現行マスタ上）」と参照ファイル根拠付きで答えること
- 5b: 「送料率は何％？」と送信。→ 「送料は計算しない運用（申し送り事項に記録）」と参照A_v2根拠で答えること。0.1と答えたら旧知識混入なので参照Aの「送料の扱い」を強調
- 5c: 「今日の大阪の天気は？」と送信。→ 案内表示が返り、AIが走らないこと

### 評価観点（モックの合否基準・6観点）
1. 列規律: **28列**の順序・数が崩れないか。送料列が復活していないか。空欄指定列が空欄か
2. 列ズレ: タブ区切りがExcelに崩れず貼れるか（商品名内のカンマ・改行で壊れないか）
3. 推測混入: 空欄にすべき項目に創作が入っていないか。価格の勝手な確定がないか
4. 分類規律: マスタ外の大分類・小分類を創作していないか
5. 正規化精度: 税抜変換の小数点保持、単位・温度帯の正規化がルールどおりか
6. 検知感度: 【要確認事項】の拾い漏れ／過剰検知のバランス。送料条件が申し送り事項に確実に入るか

### モック検証の追加観点（新SENDO設計へのフィードバック）
実運用1〜2ヶ月で以下を観察し、新SENDO商品マスタの列構成確定に反映する:
- 28列で足りない情報が申し送り事項に頻出していないか（頻出項目は列昇格の候補）
- 逆にほぼ常に空欄の列はないか（削除候補。例: JANコード・発注リードタイムの実際の記入率）
- 定価計算の基数変更（送料項なし）で、粗利率設定をどうするか（参照A_v2の要確定事項参照）

## 既知の限界と調整ポイント

| 症状 | 調整方法 |
|------|---------|
| 送料列を出力してしまう（旧知識混入） | 厳守事項の「送料関連の列は存在しない」を強調。参照Aの列一覧をプロンプト本文に直接転記 |
| 列がズレる・列数が合わない | ベースプロンプトに「出力前に列数が28であることを確認する」を追記 |
| 空欄指定列に0や計算値が入る | 厳守事項に間違えた実例（「海外定価を計算してしまう」等）をそのまま追記 |
| 小数点を丸める | 厳守事項に計算例を明記（715÷1.08=662.037037 を保持、の1行）。直らなければ拡張思考ON |
| 分類を間違える | 参照Bの判定ガイドに間違えた実例を追記（実例追記が最も効く） |
| PDFの表を誤読する | テキスト貼り付け運用に切り替え。またはExcel見積は本文にコピペしてから渡す |
| 商品数が多い見積で後半が雑になる | 1回の入力を10〜15商品に分割 |
| 温度帯の推定が過剰 | 参照Cの推定テーブルにない商品は「不明」＋要確認、をベースプロンプトに追記 |
| 判定条件の振り分けミス | 基本条件の3分類の文言を、実際の誤判定例に合わせて書き換え |
