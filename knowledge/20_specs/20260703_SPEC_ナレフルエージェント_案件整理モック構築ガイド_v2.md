## 画面2: 参照ファイル設定・応答設定

| 項目 | 設定値 | 理由 |
|------|--------|------|
| ファイル参照 | 参照01〜03のv2を3本アップロード（v1は削除） | ナレッジパックの配布コピー。正本更新時に差し替え |
| 参照ソースの詳細 | **表示する** | どの知識を根拠にしたか検証するため（モック段階では必須） |
| モデル | 選択肢の中で最上位（推論系）のモデル | 構造化抽出は軽量モデルだと列ズレ・推測混入が起きやすい |
| WEB検索 | **利用しない** | 社内データのみで答えさせ、外部情報の混入を防ぐ |

**運用メモ**:
- 週次のSansanコンタクトCSVは参照ファイルに登録せず、**チャットに都度添付（または本文貼り付け）**する。参照ファイル＝変わらない知識、チャット入力＝毎週変わるデータ、と役割を分ける
- 過去分の照会用に、月次で「処理済みコンタクト集.md」を参照ファイルに追加していく（R2想起の実装）
- **参照ファイルは配布コピー**。正本（プロジェクト知識の用語集・ルール集／SENDO SIマスタ）を更新したら、参照ファイルの差し替えをNotionタスクに起票する。参照ファイル側を直接編集しない

## 画面2続き: ベースプロンプト（コピペ用・v2）

```
あなたは新日本海商事の営業データ整理アシスタントです。Sansanコンタクト情報（CSV・貼り付けテキスト・商談メモ・チャットログ）を、SENDO台帳に転記できる構造化データに変換します。

# 動作モード（入力で自動判定）
【構造化モード】コンタクト情報が渡された場合:
1. 参照ファイル「ステージ定義と出力フォーマット」に従い、各コンタクトをA見込客/B案件/C仕入先・パートナー開拓/Dサンプルに分類する
2. 分類ごとの台帳フォーマット（タブ区切り）で行を生成する
3. KWタグは参照ファイル「KWタグ辞書とBU/SI一覧」の正規タグから選ぶ。辞書にない場合のみ【新規KW候補】として提案する
4. B案件にはBUマッチング（KW一致率＝共通タグ数÷案件タグ数、40%以上でマッチ候補）を付ける。どのBUにも40%未満なら【新規BU候補】を出力する
5. 台帳の実績（受注・リピート）がBU一覧の単価・頻度と乖離していたら【BU改訂候補】を出力する
6. 価格・条件・在庫・ルールの変化を検知したら【マスタ変更候補】【ルール変更候補】セクションを必ず見出し付きで出力する
7. 最後に「処理件数と内訳」「判断に迷った点」を1〜3行で添える

【照会モード】特定の社名・案件・仕入先についての質問の場合:
参照ファイルと過去に渡された情報の範囲で、出典（日付・登録者）を添えて答える。情報がなければ「手元の情報にはありません」と答える。

# 厳守事項
- 推測で埋めない。不明な項目は「不明」と書く
- 金額・価格・条件は出典（コンタクト日・発言者）を必ず添える
- 原文にない金額・日付を創作しない
- BU一覧の単価・頻度は仮説を含む。実績がBUと食い違っても実績側を書き換えない（乖離は【BU改訂候補】で報告）
- 進捗メモは「MMDD 何があったか →何が変わったか」形式、/区切り、左が新しい
- 社名・人名は入力の表記のまま使う
- 「決定」と「議論中」を区別し、原文のニュアンスを保つ
- 出力の台帳部分は必ずタブ区切り（Excelに直接貼れる形）にする
```

「高度なオプション」で **「詳細な判定条件を設定して、ワークフローを利用する」** を選択し、実行前をON。

**分岐判定の基本条件**（コピペ用・v1から変更なし）:

```
・構造化依頼: コンタクトCSV・商談メモ・チャットログなどの営業接点情報が添付または貼り付けされており、整理・分類・台帳化を求める内容
・照会: 特定の会社名・案件・仕入先・商材の状況や経緯を尋ねる質問
・対象外: 上記に該当しない雑談、一般知識の質問、翻訳や文書作成などの依頼
```

**判定条件とアクション**（優先度順・上から判定される点に注意）:

| 優先度 | 判定条件（コピペ用） | アクション |
|--------|--------------------|-----------|
| 1 | 営業接点情報（CSV・商談メモ・チャットログ）の添付や貼り付けを伴う、整理・分類・台帳化の依頼 | 追加アクションを実行しない（本エージェントをそのまま実行） |
| 2 | 特定の会社・案件・仕入先・商材の状況や経緯に関する質問 | 追加アクションを実行しない（本エージェントをそのまま実行） |
| 3 | 上記のいずれにも該当しない内容 | **案内表示を応答して処理を終了する** |

優先度3の案内表示テキスト（コピペ用・v1から変更なし）:

```
このエージェントは営業コンタクト情報の整理専用です。
・コンタクトCSVを添付、またはメモ本文を貼り付けて「整理して」と送ってください
・「〇〇社の件どうなってた？」という照会にも答えられます
```

**設計意図（v2で明確化）**:

## テスト手順（v2: 5本）

### テスト1: 構造化モード（正常系）
本日のcontactlist CSV（トラシェア商談）を添付し、「整理して」と送信。

**期待される出力の骨子**:
- 分類: **C. 仕入先・パートナー開拓**（トラシェアは当社に売る側＝SNSマーケ支援の提案受領。販売見込客ではない）
- 台帳行（タブ区切り）: KW=SNSマーケ/エゾシカ等、確度=C（提案の入手）、進捗メモ=「0701オンライン商談 SNS施策・飲食店起点拡販の提案受領 →検討」
- 事例企業名や「継続50社・サブスク30社」等の数字に出典（7/1・トラシェア周澤氏）が付いているか
- 金額の創作がないか（このコンタクトに見積金額はないので、単価欄は出ないのが正解）
- ※v1で【新規KW候補】だった「インフルエンサー」は、v2辞書ではSNSマーケの表記ゆれとして吸収されるのが正解

### テスト2: 照会モード
「トラシェアの強みは何だった？」と送信。→ 出典付きで導線設計まで含む支援範囲を答えられればOK。

### テスト3: 対象外の入力
「今日の大阪の天気は？」と送信。→ 案内表示が返り、AIが走らないこと。

### テスト4: 変更候補検知（メール送信の確認）
Slackログの一部（例: 「レバー在庫アリで仕入¥1,400/kg税別」「発注ルール①〜③」の箇所）を貼り付けて「整理して」と送信。→ 【マスタ変更候補】【ルール変更候補】が出力され、**オーナー宛メールが届くこと**。

### テスト5: BUマッチング（v2追加）
B案件相当のダミーコンタクトを貼り付けて「整理して」と送信。2パターン:
- **5a（マッチあり）**: 「イタリアン○○（客単価1.2万）からエゾシカモモ月5kg定期の引き合い、単価2万で見積依頼」→ 案件台帳行＋【BUマッチング】BU-01（一致率75%以上）が出ること。BU-01の頻度推定（月1）と食い違う情報があれば【BU改訂候補】が出ること
- **5b（マッチなし）**: BU一覧のどれとも重ならないKW構成（例: 熊肉×百貨店催事）→ 「マッチなし（新規BU候補の種）」＋【新規BU候補】セクションが出ること。BU一覧の値に引きずられた創作（単価の勝手な補完）がないこと

### 評価観点（モックの合否基準・v2で6観点に）
1. 分類精度: A〜Dの仕分けが人間の判断と一致するか
2. 列ズレ: タブ区切り出力がExcelに崩れず貼れるか（サンプル台帳13列を含む）
3. 推測混入: 「不明」と書くべき欄に創作が入っていないか
4. KW規律: 辞書外タグを勝手に使わず【新規KW候補】経由になっているか
5. 検知感度: 価格・ルール変化の拾い漏れ／過剰検知のバランス
6. **BU規律（v2追加）**: マッチ率計算が正しいか／マッチなし時に【新規BU候補】へ流れるか／BU一覧の仮説値で実績を上書きしていないか

## 既知の限界と調整ポイント

| 症状 | 調整方法 |
|------|---------|
| 分類を間違える | 参照03の判定基準に具体例を追記（間違えた実例をそのまま入れるのが最も効く） |
| 参照ファイルを見ずに答える | ベースプロンプトに「必ず参照ファイルの定義に従う」を強調、またはファイル名を明示して指示 |
| CSVの列を誤読する | CSVヘッダの説明（コンタクト日/社外出席者/メモ/登録者の意味）を参照01に追記 |
| 長いCSVで後半が雑になる | 1回の入力を10〜20件に分割。または実行後分岐の「次エージェント連続実行」で分担 |
| 判定条件の振り分けミス | 基本条件の3分類の文言を、実際の誤判定例に合わせて書き換え |
| BUマッチングの一致率計算を誤る | ベースプロンプトに計算例を1つ明記（例: 案件KW4個中2個共通→50%） |
| 【BU改訂候補】が出すぎる | 「乖離」の閾値を定義（例: 単価が一覧の値の±50%を超える場合のみ）して参照03に追記 |
