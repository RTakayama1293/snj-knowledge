## Part 2: 組織4層構造【v3新規追加】

### 2-1. 商事の業務を4つの層に分離する

9人の小規模組織では、1人が複数層を兼務するのが現実。問題は「どの層が存在しないか」を認識しないまま運営すること。v3では層を明示し、誰が何層を担うかを定義する。

```
┌───────────────────────────────────────────────────┐
│ 経営層：方針決定・資源配分・対外折衝               │
│ 蜂巣さん                                          │
├───────────────────────────────────────────────────┤
│ 企画層：KPI設計・分析・改善提案・長期戦略          │
│ 高山（← v3で明示）                                │
├───────────────────────────────────────────────────┤
│ 管理層：月次数値の締め・モニタリング・異常検知      │
│ 飛石さん（← v3で拡張）                            │
├───────────────────────────────────────────────────┤
│ 実行層：受発注・出荷・営業・問い合わせ対応         │
│ 田嶋さん／松本さん／杉田さん／永井さん／黒田さん   │
└───────────────────────────────────────────────────┘
```

### 2-2. 各層の定義

**実行層**：日々の取引を回す。受発注処理、出荷手配、請求発行、入金確認、営業活動、コンテンツ制作。成果は件数・金額で測定できる。

**管理層**：月次で数字を締めて可視化する。売掛金残高表の作成、与信枠との突合、入金消込の確認、滞留債権の検知、松田さんへの報告。実行層が「回す」ために「見える化」する仕事。

**企画層**：KPIを設計し、管理層が作った数字を読み解き、実行層の動き方を変える提案をする。仕組みの構築・改善、システム導入検討、商材別収益構造分析、新規チャネルの試算。四半期〜年単位で回す。

**経営層**：企画層の提言を受けて意思決定し、リソースを配分し、親会社・取引先との関係を管理する。

### 2-3. 現状の問題と解決

v2まで：蜂巣さんが経営＋企画＋管理を兼務、営業が実行＋管理を兼務、管理層が実質不在。結果として「数字で経営する」が構造的に不可能だった。

v3で：飛石さんが管理層を担い、高山さんが企画層に専念する。蜂巣さんは経営層に集中できる。

### 2-4. 高山の企画機能【v3新規定義】

飛石さん・松本さん・田嶋さんが「回す」ためのシステム設計・KPI設定・異常検知の仕組みを作り、飛石さんから上がる数字を読み解いて「次に何をすべきか」を蜂巣さんに提言する。

具体的なアウトプット：

| 機能 | 具体例 | サイクル |
|------|-------|---------|
| KPI設計 | 三者の判定基準、型A/B/C分類、与信モニタリング指標 | 四半期 |
| 分析 | 商材別粗利率推移、取引先ポートフォリオ偏り、季節変動パターン | 月次 |
| 改善提案 | 営業リソース配分見直し、オペレーション改善、システム改修 | 随時 |
| 長期企画 | EEZO再構築、BtoCチャネル戦略、海外市場優先順位、新商材収益シミュレーション | 四半期〜年次 |
| 仕組み構築 | SENDO次フェーズ、案件収支管理改善、Sansan運用最適化 | プロジェクト単位 |

企画層の価値は時間で測れない。「これがなければ意思決定できなかった」と言える成果物を定期的に出し続けることが正当化の根拠。

### 3-2. 飛石さん：詳細設計【v3全面改訂】

**公式肩書**: 営業事務（内勤営業兼務）
**実態**: スタートアップバックオフィス一人目
**勤務形態**: 時短勤務 80-100h/月（9:30-15:30想定）

#### 設計思想：「営業が売る、仕入が買う、その間と周辺の全部」

9人の組織に専任の経理部も総務部も法務部もない。今まで蜂巣さん・松田さん・営業が属人的に回していた「仕組みで回すべき業務」を、飛石さんが一人で立ち上げる。公式には「営業事務」だが、実態はスタートアップのバックオフィス機能そのもの。

#### 経理/財務の境界定義【v3新規】

飛石さんの守備範囲を明確にするため、経理（会計記録・フロー管理）と財務（資金判断・信用決定）の境界を定義する。

| 区分 | 飛石さん（経理＋モニタリング） | 蜂巣さん＋松田さん（財務判断） |
|------|---------------------------|---------------------------|
| 請求・入金 | 請求書発行、入金確認、消込処理 | — |
| 売掛金 | 残高表作成、与信枠との突合、滞留検知 | 回収方針の決定、取引停止判断 |
| 与信管理 | 信用調査の発注、評点記録、枠算定の下準備 | 与信枠の最終承認（個別稟議） |
| 支払遅延 | 遅延事実の検知と報告 | 対応方針の決定（督促・取引見直し等） |
| 仕入・買掛 | 買掛金残高管理、支払期日の管理 | 支払条件の交渉 |
| 管理会計 | 月次集計資料の作成 | 数字に基づく経営判断 |

原則：**飛石さんは記録・集計・検知・報告まで。判断・交渉・決定は蜂巣さん＋松田さん。**
ただしPhase 3以降、経験と信頼が蓄積すれば、判断の一部を委任していく拡張余地がある。

#### キャパシティ分析

Phase 1（4-6月）では管理会計(E)はまだ本格稼働せず、代わりに以下の「仕組み構築」初期負荷が乗る：
- ガリレオの操作習得：+10-15h（最初の2ヶ月）
- 契約書棚卸し：+10-15h（最初の1ヶ月）
- 与信管理のフォーマット整備：+5-8h（最初の1ヶ月）
- 証憑管理の保存体制構築：+5-8h（最初の2ヶ月）

結果として、Phase 1は仕組み構築で80-100hをほぼ使い切る。Phase 2で定常化し管理会計が加わる。Phase 3で取引量増加が変動部分を押し上げる。自然なキャパシティの推移になる。

```
Phase 1（4-6月）：仕組み構築期
├─ 定常業務 50-65h + 初期構築 20-40h ≒ 70-100h（フル稼働）

Phase 2（7-9月）：定常運用＋管理会計導入
├─ 定常業務 54-75h + 管理会計立ち上げ ≒ 60-85h（やや余裕）

Phase 3（10月～）：取引量拡大で吸収
├─ 田嶋さん国内営業本格化 → 変動業務(B)が月+5-10h
├─ Shopify移行 → toC注文増 → 変動業務(B)が月+3-5h
├─ 定常業務 60-85h程度（キャパ内で自然に推移）
```

#### 制約C1の解消ロジック

稟議文言「内勤営業/営業事務」と実態のマッピング：

```
稟議の看板                    実態の内容
─────────────────────────    ──────────────────────
営業事務（見積・請求対応）  → 受発注サイクルの事務処理 + ガリレオでの入金管理
営業事務（契約書管理）      → 取引に伴う契約書管理 = 法務機能
営業事務（庶務・社内調整）  → 総務・庶務 + 証憑管理
内勤営業（顧客対応窓口）    → toC問合せ = 売上に直結する窓口業務
営業事務（受発注管理補助）  → 貿易学習（松本下）
営業事務（経理連携）        → ガリレオ運用 + 与信管理 + 月次管理会計
```
