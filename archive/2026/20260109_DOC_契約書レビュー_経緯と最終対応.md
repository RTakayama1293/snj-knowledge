### Step 4: 契約類型の再検討（請負 vs 準委任）

チェッカー指摘を精査した結果、以下が判明。

**チェッカーの前提条件**:
> 「お客様が選択した類型を前提として」

つまり、総務がチェッカーにかける際に「システム開発委託個別契約（請負型）」を選択したため、請負前提で指摘が出ていた。チェッカーは契約書の実態を読んで判断したわけではない。

**エディ契約の実態分析**:

| 観点 | 実際の状況 | 示唆する類型 |
|------|------------|--------------|
| 報酬体系 | 月額固定 | 準委任的 |
| 報酬発生条件 | 期間経過（完成物の有無に関わらず） | 準委任的 |
| 契約の継続性 | 12か月の継続契約 | 準委任的 |
| 働き方 | 社内システム担当的ポジション | 準委任的 |

**結論**: 実態は準委任的要素が優勢。ただし、稟議書で「初期構築」「成果物」という記載があるため、完全に準委任と整理するのは稟議との整合性に疑問が残る。

### Step 5: 蜂巣さんとの協議

蜂巣さんとの会話で以下が判明。

**総務からの連絡の趣旨**:
- 「参考までにチェック結果を送るので確認してください」というニュアンス
- 全指摘への対応が必須ではない

**対応方針の決定**:
- 契約自由の原則に立ち返り、実態に合っていて双方合意できればOK
- 請負/準委任の明示は藪蛇リスクがあるため行わない
- 成果物条項は形式的に揃えるが、実質的な縛りは入れない
- 請負固有項目（検収・契約不適合責任・品質保証等）は追加しない

## 3. 最終対応

### 対応方針

| 項目 | 方針 |
|------|------|
| 契約類型 | 明示しない（請負/準委任のどちらとも取れる形） |
| 成果物条項 | 追加するが協議ベースで実質的縛りなし |
| 検収・契約不適合責任 | 追加しない（現行の「補完」条項で対応） |
| 知的財産権 | 両契約とも拡充（最重要項目） |
| その他標準条項 | 両契約で揃える形で追加 |

### 堀田契約：過剰項目の削除

当初修正案から以下を削除・簡略化。

| 項目 | 対応 | 理由 |
|------|------|------|
| 業務報告 | 削除 | 日常的にやり取りしており不要 |
| 業務遂行状況の確認 | 削除 | 同上 |
| 反社会的勢力（5項構成） | 簡略化（2項） | 月5万円契約には過剰 |
