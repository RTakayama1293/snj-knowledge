## 1. 出発点

「EEZOの販売計画をしっかり作って、あとあと運用できるようにしたい」という起点から、単なるタスクリストや計画書ではなく、SFA/CRM/CMSに近い**事業オペレーションの管理基盤**が必要という結論に至った。

### 既にあったもの（戦略レイヤー）

- タスクマップv4（3/5）: 全観点のタスク分解とクリティカルパス
- B/C棲み分けサイトマップ（3/30）: Shopifyのページ構造とユーザー導線
- 商品構造設計（4/2）: 3ジャンル×3価格帯の9セルマトリクス
- 商品名・説明文v7（4/13）: 25SKUの商品データ
- 収益モデル（3/3）: 短期15M / 中長期100Mの2フェーズ設計

### 足りなかったもの（運用レイヤー）

月別×商品×チャネルの実行カレンダー、予算配分、KPI追跡、予実比較。つまり「毎月開いて進捗を見て、次の施策を決める」ための数字入りの管理基盤。

## 2. ツール選択の経緯

### 検討した3つのアプローチ

**チャット（Claude.ai）**: プロジェクトナレッジを横断参照しながら構造設計するフェーズに最適。最終的にここで設計・作成した。

**Cowork + Dispatch + Google Drive**: Google Sheetsをリアルタイム編集する運用フェーズ向き。初期設計には不向き。

**CCW（Claude Code on the Web）**: コード資産が残る用途向き。販売計画には重い。

→ **初期設計はチャット、成果物はxlsx** で進行。

### Excel vs Notion の判断

| 観点 | Notion | Excel |
|------|--------|-------|
| リレーションDB | 素で持っている | テーブル+SUMIFSで擬似的 |
| ビューの追加 | タイムライン/ボード/テーブルを1クリック | シートコピー+数式設定 |
| イベントGantt | タイムラインビューそのもの | 条件付き書式で代用 |
| Power Query | なし（Zapier迂回のみ） | Shopify CSV自動取込 |
| 複雑集計・P/L | rollup/formulaでは力不足 | PivotTable/数式で自在 |
| SENDO統合パス | 変換が必要 | Excel→Excelで直線的 |
| 二重管理 | Notionハイブリッドだと同期コスト発生 | 一元管理 |

**結論: Excel統合**。同期コストゼロの方が9人体制の運用に合う。Notionはタスク管理に専念させ、販売管理はExcelに閉じる。

## 3. アーキテクチャ設計

### 初期案: 4層構造（DASH_層）

```
DEF_(マスタ) → PLAN_(計画) ←→ ACT_(実績) → DASH_(分析)
```

DASH_層を「自動計算の分析ダッシュボード」と定義したが、ここにイベントGantt（運用ツール）、年間P/L（財務帳票）、施策パフォーマンス測定（運用振り返り）も置く必要があり、層の性質が混在する問題が発生。

### 改訂案: VIEW_層（プラグイン式）

```
DEF_(マスタ) → PLAN_(計画) ←→ ACT_(実績)
                      ↓
              VIEW_(ビューレイヤー) ← プラグイン式・自由追加
```

VIEW_層を3種に分類:

- **分析系**: KPIサマリー、カテゴリ別予実、月次トレンド（PLAN vs ACTの自動突合）
- **運用系**: イベントGantt、施策パフォーマンス、チャネル別ROI（日々の管理）
- **財務系**: 年間P/L、コスト予実（蜂巣さん報告用帳票）

データ層（DEF_/PLAN_/ACT_）はExcelテーブル（ListObject）として構造固定。VIEW_層はテンプレートをコピーして自由に追加できる設計。データ層に触らずにビューだけ増やせるのがポイント。

### SENDO統合の設計原則

1. **マスタの分離**: SKU・仕入先のマスタは独立シート。将来SENDOとマージ可能
2. **計画と実績の構造的対称性**: 同一キー（カテゴリ×月）でPLAN/ACTを突合
3. **採番ルールの継承**: SKUコードは `PRD_SNJ_XXX_0000_00` 形式を踏襲

## 6. ダッシュボードで想定しているまとめの種類

設計過程で洗い出した7種 + 追加要望3種:

### 当初設計（7種）

1. **月次KPI**: 売上/注文数/客単価/粗利の4指標。達成率で色分け
2. **カテゴリ別予実**: 12カテゴリの達成率テーブル + 構成比
3. **月次トレンド**: 計画vs実績の12ヶ月推移折れ線
4. **イベント効果**: イベント期間中の売上を通常期ベースラインと比較
5. **チャネル別パフォーマンス**: SNS/メルマガ/広告/O2Oの CPA/ROAS横比較
6. **コスト予実**: 科目別の予算消化率
7. **アラート**: 閾値ベースの自動検知（達成率85%未満で赤、95%未満で黄）

### 追加要望（3種）

8. **イベント単位のToDo Gantt**: 施策の進捗・期日を条件付き書式で可視化
9. **年間P/L**: 月次積み上げ損益計算書。蜂巣さん報告に使う
10. **施策別パフォーマンス**: 個別キャンペーン（例: 母の日LP × Instagramカルーセル）単位の効果測定

→ これらを収容するため、DASH_層をVIEW_層に再定義し、分析系/運用系/財務系の3種に分類した。

## 8. 設計過程で見送ったもの

- **Notionハイブリッド**: 運用系ビュー（Gantt等）はNotionが強いが、同期コストと二重管理リスクで見送り
- **Google Sheets版**: IMPORTRANGE同期は案件収支管理v2で実証済みだが、PQが使えないため見送り
- **CCW（Claude Code on the Web）**: コード資産が残る用途向き。管理シートには重い
- **Cowork + Dispatch**: 運用フェーズでの月次更新には有効。設計完了後に再検討の余地あり
