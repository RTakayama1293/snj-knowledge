## 📋 **経緯・背景**

### **課題発見の経緯**
2025年9月下旬、ユーザーが受発注業務を担当することになり、以下の「ファッキン面倒なブルシットジョブ」課題を発見：

#### **発見された根本問題**
1. **発注書・請求書のダブルミーニング**：仕入先用/販売先用の区別が不明確
2. **見積もりのPDF化問題**：データ再利用不可、構造化されていない
3. **見積=価格表問題**：数量未確定での概算、正式数量との齟齬（cf.魚国案件）
4. **全書類手入力**：転記ミス・工数増大の温床
5. **納品書フローの複雑化**：送り状番号の伝言ゲーム発生
6. **進捗と営業の分離**：Excel管理による情報分断

### **既存SENDO設計との適合性**
既存のSENDO統合営業DXプラットフォーム設計を確認した結果、**受発注業務の課題解決に完璧に適合**することが判明。特にExcel自動化エンジンとSansan統合機能が、発見された課題の直接的解決策として機能することが確認された。

## 🚀 **アップデート内容**

### **1. 書類管理システムの大幅強化**

#### **実務ノウハウとの統合**
外部の実務ノウハウ文書「取引先向け見積書／請求書表記の実務対応とノウハウ」を参考に、以下を実装：

##### **自動書類種別判別システム**
```vba
Function DetermineDocumentType(dealID As String) As String
    Dim dealRole As String
    dealRole = GetDealRole(dealID) ' Sansanから自動取得
    
    Select Case dealRole
        Case "販売先"
            DetermineDocumentType = "SALES" ' 青系テンプレート・丁寧語
        Case "仕入先"  
            DetermineDocumentType = "PURCHASE" ' 緑系テンプレート・内部用語
    End Select
End Function
```

##### **自動採番・命名システム**
- **番号体系**: QR-YYYY-XXX（販売見積）/ PQ-YYYY-XXX（仕入見積）/ SI-YYYY-XXX（売掛請求）/ PI-YYYY-XXX（買掛請求）
- **ファイル命名**: 「QR-2025-001_御見積書_株式会社A様.pdf」形式で自動生成
- **視認性向上**: 販売用（青系ヘッダー）/ 仕入用（緑系ヘッダー）の自動適用

#### **段階的数量管理システム**

## 🎯 **統合後の業務フロー**

### **理想的な受発注プロセス**

#### **Stage 1: 見積段階**
1. 杉田さんがSansan上で「見積依頼」ステータスに変更
2. **SENDO自動処理**：
   - 取引先種別を自動判別（販売先/仕入先）
   - 適切な番号採番（QR-2025-001等）
   - 色分けテンプレート自動選択
   - 顧客・商品マスタから見積書自動生成
   - PDF出力（命名規則準拠）
3. 杉田さんに「見積書準備完了」Slack通知
4. 杉田さんがメール送信・フォロー

#### **Stage 2: 発注段階**
1. 正式数量確定後、「受注確定」ステータス変更
2. **SENDO自動処理**：
   - 仕入先発注書自動生成（緑系テンプレート、PQ番号）
   - 販売先受注確認書生成（青系テンプレート、QR番号）
   - 数量履歴の確定版記録
   - 進捗管理への自動登録
3. 営業に確認・送信依頼通知

#### **Stage 3: 納品・請求段階**
1. 「納品」ステータス変更
2. **SENDO自動処理**：
   - 送り状番号の自動取得・顧客納品書への反映
   - 請求書データ準備（SI番号採番）
   - 顧客向け納品連絡の準備
3. 営業による最終確認・送信

## 💡 **追加検討事項**

### **緊急対応が必要な課題（TBD）**
#### **見積書の種別区分問題**
**発見日**: 2025年9月26日  
**課題内容**: 見積書に以下2つの異なる性質があり、システム上で区別が必要
1. **カタログ的見積**: 価格表・商品紹介用途、複数顧客に同じ内容を配布
2. **個別作成見積**: 特定顧客向けにカスタマイズした正式見積

**影響範囲**:
- 書類管理の複雑化（同じ「見積書」でも用途が異なる）
- ファイル命名規則の見直し必要性
- 営業プロセスでの取り扱い方法の明確化
- システム上での自動判別機能の必要性

**検討すべき実装案**:
```vba
' 見積書種別の自動判別システム（案）
Function DetermineQuoteType(dealID As String) As String
    If IsCustomSpecific(dealID) Then
        DetermineQuoteType = "CUSTOM_QUOTE"    ' QC-番号
    Else
        DetermineQuoteType = "CATALOG_QUOTE"   ' QT-番号  
    End If
End Function
```

**対応優先度**: 高（システム設計の根幹に関わるため）  
**対応期限**: Phase 1実装前までに仕様確定必須  
**担当**: 営業チーム（使い分け基準）+ システム管理者（技術実装）
