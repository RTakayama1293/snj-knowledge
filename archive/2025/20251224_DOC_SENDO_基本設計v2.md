## 📋 改訂の背景

### 当初設計からの主な変更点

| 項目 | v1（当初設計） | v2（本設計） | 変更理由 |
|------|---------------|-------------|---------|
| データ層 | Sansan中心 | **DWH中心（PostgreSQL）** | SansanのAPI制約（読み取り専用） |
| CRM機能 | Sansanで案件管理 | **DWHで自前管理** | 書き込みAPIなし、結局Excelが正に |
| Sansanの役割 | 中央ハブ | **名刺DB + 配信ツール限定** | 機能を割り切り |
| 通知手段 | Slack / LINE Notify | **メール（eezo.club）** | LINE Notify終了（2025年3月） |
| 技術基盤 | Excel VBA | **DWH + エディ協業** | 長期的な拡張性確保 |
| 実装体制 | 内製中心 | **エディと協業** | 専門知見の活用 |

### 変更に至った課題認識

1. **SansanのCRM限界**
   - APIが読み取り専用（書き込み不可）
   - 名刺インポート・配信は便利だが案件管理には使えない
   - 結局Excelが「正のデータ」になっている

2. **LINE Notify終了**
   - 2025年3月31日でサービス終了済み
   - Messaging APIは月200通制限（実運用では有料化必須）
   - メール通知（eezo.club）で代替

3. **エディのリソース活用**
   - 月次コストに余裕がある
   - DWH構築の知見あり
   - 最初からちゃんとした基盤を作る方が長期的にROI高い

## 📊 データ層の定義

### Data Lake (DL)

**目的**: 生データを加工前の状態で保存し、将来の分析・再処理に備える

**実装案**: Google Drive（専用フォルダ）またはGoogle Cloud Storage

```
📁 SENDO_DataLake/
  ├── 📁 sansan/
  │     ├── 2025-01-15_contacts.csv
  │     ├── 2025-01-22_contacts.csv
  │     └── ...
  ├── 📁 eezo/
  │     ├── 2025-01-15_orders.csv
  │     └── ...
  ├── 📁 exhibition/
  │     ├── 2025-07_foodex_leads.xlsx
  │     └── ...
  └── 📁 instagram/
        └── ...
```

**DLを持つ意義**:
- 生データを捨てない → 後から「あのデータ欲しかった」に対応可能
- ETL失敗しても元データは残る → やり直しが効く
- 非構造化データも置ける → 将来の機械学習用途など

### Data Warehouse (DWH)

**目的**: クレンジング・正規化済みの「正のデータ」を管理

**実装案**: PostgreSQL（Supabase等）※エディと相談

**管理エンティティ**:

| カテゴリ | テーブル | 説明 |
|---------|---------|------|
| **マスタ系** | 顧客マスタ | 会社・担当者情報 |
| | 仕入先マスタ | 仕入先・担当者情報 |
| | 商品マスタ | 商品・価格情報 |
| | 担当者マスタ | 社内担当者 |
| | 設定マスタ | 採番ルール等 |
| **トランザクション系** | 案件 | 商談・取引情報 |
| | 案件明細 | 案件内の商品明細 |
| | 書類履歴 | 生成した書類の履歴 |
| | 活動履歴 | 営業活動の記録 |

### Data Mart (DM)

**現時点では不要**

将来的に需要が出た場合、VIEWから始めて段階的に整備：
- 営業分析用DM
- 経理連携用DM

## 🔄 データフロー

### インプット（DLへ）

| ソース | 形式 | 頻度 | 取り込み方法 |
|--------|------|------|-------------|
| Sansan | CSV | 週次 | 手動エクスポート → DL保存 |
| EEZO（CS-cart） | CSV/API | 日次 | 自動/手動エクスポート |
| 展示会リード | Excel/CSV | イベント後 | 手動アップロード |
| Instagram | CSV | 月次 | Insights手動エクスポート |
| 手入力（案件等） | 入力UI | 随時 | 直接DWHへ |

### ETL（DL → DWH）

- クレンジング（欠損値処理、表記揺れ統一）
- 正規化（マスタとの紐付け）
- 重複排除（名寄せ）
- バリデーション

### アウトプット（DWHから）

| 出力 | 形式 | トリガー |
|------|------|---------|
| 見積書 | PDF | 案件ステータス変更 or 手動 |
| 発注書 | PDF | 受注確定時 |
| 請求書 | PDF | 納品完了時 |
| 通知メール | eezo.club | 各種イベント |
| ダッシュボード | Web（将来） | オンデマンド |

## 📧 通知システム

### 採用: メール（eezo.club）

**理由**:
- LINE Notify終了（2025年3月）
- Messaging APIは有料化必須（月200通制限）
- eezo.clubのWebmail基盤が既にある
- 社外でも受信可能

**通知対象イベント**:
- 見積依頼発生
- 受注確定
- 納品完了
- 請求書発行
- エラー・アラート

**通知先**:
- 営業担当者
