## 2. アーキテクチャ

**正本（SSOT）= GitHubリポジトリ `snj-knowledge`（新規作成・プライベート）**

```
                 ┌─────────────────────────┐
                 │  GitHub: snj-knowledge  │  ← 正本。全編集はここに集約
                 └───────────┬─────────────┘
        ┌────────────────────┼────────────────────┐
   git pull/push        Coworkセッションで         CCWがrepo直結
        │               clone→project_write        │
┌───────┴────────┐   ┌───────┴────────┐   ┌───────┴────────┐
│ 在宅ローカルCC │   │ webプロジェクト │   │      CCW       │
│ (nucbox)       │   │ （配布コピー）  │   │ (repo=正本参照) │
└────────────────┘   └────────────────┘   └────────────────┘
```

- **ローカルCC / CCW**: リポジトリを直接読むので、pull さえすれば常に正本と一致
- **webプロジェクト**: RAG用の**配布コピー**。`sync/project_manifest.md` に載っているファイルだけを置く（正本セット＋索引）。方向は repo → project の一方向
- **ナレフルチャット等の配布コピー**: 既存ルール（正本更新→Notionタスク起票→差し替え）を踏襲。正本の所在が repo に変わるだけ

## 4. 同期ルール（SYNC_RULES.mdの骨子）

1. **編集は正本で行う**。ローカルCC・CCW・Coworkセッションいずれで編集しても、必ずrepoにコミットして完結とする
2. **バージョン管理はGitに任せる**。今後の更新は「_v6」を作らず同名上書き＋コミット。既存ファイル名は移行時点のまま維持（リンク切れ防止）
3. **webプロジェクトは配布コピー**。project_manifest.mdにあるファイルのみ配置。更新反映は（a）正本にまとまった変更が入ったとき、（b）最低でも月次、のいずれか早い方。Coworkセッションで「プロジェクト同期して」と依頼すればrepo→projectの差分反映を実行できる
4. **チャット発の新規成果物**は従来どおりまずプロジェクトに保存してよい。ただし週次で `_inbox/` 経由でrepoに取り込み、カテゴリに振り分ける（振り分け作業もCowork/ローカルCCに依頼可能）
5. **配布コピーを直接編集しない**（ナレフル参照ファイル・webプロジェクトとも）。直したくなったら正本を直して再配布
6. **アーカイブは削除しない**。archive/へ移動し、プロジェクト（RAG）からは外す
